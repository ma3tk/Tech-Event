# アンケート機能 (event-survey.md)

connpass のアンケート (イベントフォーム) 機能、申込時の回答収集、CSV ダウンロード、参加後フィードバックについての調査。

## 1. 機能の目的

connpass のアンケート機能は、**イベント申込フォームに任意の質問項目を追加し、申込者全員から回答を集める** ためのものである。役割は次の通り。

- 参加者属性 (経験年数・職種・参加目的) を事前に把握して当日の進行をチューニング
- 教材 / ノベルティ / 食事の選択を事前に集計 (例: アレルギー、Tシャツサイズ)
- 学生 / 一般 / スポンサーといった参加カテゴリの自己申告
- 当日のグループ分けや席順の参考データ

connpass の現行仕様では、アンケートは **「申込フォーム同梱」** のみが正式機能で、純粋な「参加後フィードバックフォーム」は標準提供されていない。事後アンケートは「参加者への情報」欄に Google Forms / Typeform 等の外部リンクを貼って運用するのが慣習。

公式の説明:
> 回答は参加申し込みと同時に行われ、申し込み後はキャンセルしないと再回答できません。

## 2. 利用シナリオ

| シナリオ | 質問形式 | 用途 |
|----------|----------|------|
| 経験年数の把握 | ラジオボタン | 初心者向け / 上級者向け配分 |
| 興味のあるトピック (複数選択) | チェックボックス | LT セッションの配分 |
| 食事アレルギー | フリーテキスト | 懇親会の食事手配 |
| 学生/社会人/その他 | プルダウン | 学割の自己申告 |
| 自由意見・期待すること | フリーテキスト | 主催者の準備材料 |
| Tシャツサイズ | プルダウン | ノベルティ手配 |

## 3. 関連エンティティ・フィールド

```
EventSurvey
├─ event_id
├─ questions: [Question]
│   ├─ id, order
│   ├─ label: string (質問文)
│   ├─ type: enum {free_text, checkbox, radio, dropdown}
│   ├─ options: [string] (radio/checkbox/dropdown 用、free_text は空)
│   ├─ required: boolean
│   └─ visible_to_participants: boolean (他の参加者からの可視性、通常 false)
└─ updated_at

Answer
├─ application_id (申込み単位)
├─ question_id
├─ value: string | string[] (chekcbox の場合は配列)
└─ answered_at
```

質問が削除されると、紐付く回答データも削除される (公式注意点)。

## 4. UI 上の入口と画面

### 4.1 主催者側

- イベント編集画面の「アンケート」セクション
  - 「質問を追加」ボタンで質問行を増やす
  - 各質問: ラベル / 質問形式 / 選択肢 / 必須フラグ
  - 過去のアンケートを「複製」する機能 (過去イベントの管理画面から)
- イベント管理ページの「申込者の管理」タブ
  - 申込者一覧 + 各人の回答を一覧で確認
  - 「CSV ダウンロード」リンクで全申込者の回答を CSV エクスポート

### 4.2 参加者側

- イベント申込フォームの一部としてアンケートが表示される
- 申込ボタンを押す前に回答必須項目を埋める
- 申込完了後は **キャンセルしないと回答を変更できない**

## 5. 外部サービス連携

connpass のアンケート機能は **内部完結** で、外部 API 連携や Webhook 通知はない。事後アンケート (NPS、満足度) を取りたい場合は以下を併用するのが慣習:

| 外部サービス | 用途 |
|--------------|------|
| Google Forms | 事後アンケート (URL を「参加者への情報」欄に掲載) |
| Typeform | UI のリッチさを求める場合 |
| Slido / Mentimeter | リアルタイムアンケート (登壇中の投票) |
| Microsoft Forms | 法人向けの集計に強い |

connpass API v2 で `applications` を取得しても、現状アンケート回答はレスポンスに含まれない (= 第三者集計ツールは CSV ダウンロード経由が前提)。

## 6. ルール・制約

- 申込と同時にしか回答できない (= 後付けで追加質問を聞けない)
- 申込済みユーザーの回答変更は「キャンセル → 再申込」しか手段がない
- 質問内容が空のまま保存されたアンケート項目は表示されない (バリデーション)
- 質問削除 = 既回答データも削除されるため、運用上は「質問非公開」のような soft delete が望ましい
- 質問数の上限は公式に明記されていないが、UX 上は 5 〜 10 問が現実的
- 回答は基本的に主催者のみが閲覧 (他参加者には公開されない)
- フリーテキストでも文字数上限がある (UI ベース推測で 1000 字程度)

## 7. 模倣実装時の代替案

### 7.1 アンケート機能の拡張案

connpass の制約を超える機能追加:

| 拡張 | 詳細 |
|------|------|
| **回答後の編集を許可** | 申込後でも参加者がマイページから回答を変更可能に。主催者側は最終提出版を CSV/UI で確認。 |
| **事後アンケート** | イベント終了後に自動メール送信し、参加者が回答するフロー。 |
| **NPS スコア** | 0-10 のスケール質問形式を追加し、NPS を自動集計。 |
| **匿名アンケート** | 参加者を特定しないモードを追加。フィードバック取得の心理的ハードルを下げる。 |
| **公開アンケート** | LT のテーマ投票等、参加者間で結果を共有するモード。 |
| **条件分岐** | 「Yes と答えた人にだけ次の質問を出す」分岐ロジック (Typeform 相当)。 |
| **CSV/Webhook 連携** | 申込時に Webhook で外部 (Slack / Notion / スプレッドシート) に push。 |

### 7.2 データ設計

```typescript
// 質問削除 → 回答も削除という強結合は避ける
type Question = {
  id: string;
  status: 'active' | 'archived';  // 物理削除しない
  // ...
};

type Answer = {
  questionSnapshot: { label: string; type: QuestionType; options: string[] };
  // 質問が削除されても回答時点のラベルを保持
};
```

### 7.3 UI / UX

- 質問は drag & drop で並び替え可能に
- プレビューモード (参加者目線でフォームを試せる)
- 「保存して下書きに戻す」「公開してフォーム凍結 (申込開始後の編集制限)」のステップ管理
- 申込開始後に質問を **追加・削除すると既申込者と新規申込者の整合性が崩れる** ため、申込開始後の編集は厳しく制限する

### 7.4 集計・可視化

- 主催者向けに簡易ダッシュボード (円グラフ・棒グラフ) を提供
- CSV ダウンロードに加えて、 Google Sheets / Notion DB へのワンクリック同期
- 申込者 = 参加確定者ではないため、「補欠 / 確定 / キャンセル」のフィルタを集計時に切り替えられるようにする

### 7.5 プライバシー

- アンケート回答は個人情報を含む可能性がある (アレルギー・所属など) ため、参加者は「主催者のみが閲覧します」と明示する同意 UI を用意。
- 主催者の退会 / イベント削除時の回答データの取扱いポリシーを利用規約に明記。
- GDPR / 個人情報保護法対応として、参加者本人による回答ダウンロード・削除リクエストを受け付けるフロー。

### 7.6 事後フィードバック (差別化機能)

- イベント終了 24h 後に自動でアンケートメールを送信。
- 「総合満足度 (1-5)」「登壇別評価」「次回参加意向」を標準テンプレートとして提供。
- 集計結果を主催者ダッシュボードに統合し、グループ単位での経時推移を可視化。

### 7.7 リアルタイム投票連携

- 当日のセッション中投票には、外部の Slido / Mentimeter / sli.do のリンク埋め込みを推奨。
- 自前で実装する場合は WebSocket + Redis で軽量に実装可能だが、運用コストに見合うかは利用頻度次第。
