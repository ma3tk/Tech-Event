# ランキング・ポイント・スコア (ranking-points.md)

connpass のイベントランキング機能、グループランキング、Findy など外部レポートで言及されるスコア指標についての調査。

## 1. 機能の目的

connpass は、ゲーミフィケーション的な「ユーザー個人のスコア・ポイント」は **持っていない** (公式機能としては未確認)。代わりに以下のランキング系コンテンツがある:

- **イベントランキング** (`/ranking/`): 直近開催の人気イベントを申込数順で表示
- **月別イベントランキング** (`/ranking/YYYY/M/`): 過去の月単位での人気イベントアーカイブ
- **新着グループ** (`/recent_group/`): 新規グループの時系列リスト
- **グループメンバー数ランキング** (アーカイブ的に存在、過去 SlideShare 資料で言及)

目的は次の通り:
- イベント発見性の向上 (新規ユーザーの初回エンゲージメント)
- 主催者へのモチベーション (上位掲載されることが運営価値に直結)
- プラットフォームの活性度を外部に対して可視化 (PR 効果)

connpass 自体は「参加者・主催者ともに『活動者』である」というフラットな思想を公式に掲げており、**個人をスコア化してランク付けする機能は意図的に避けている** とも解釈できる。

## 2. 利用シナリオ

| シナリオ | アクセス先 |
|----------|------------|
| 今もっとも盛り上がっているイベントを知りたい | `/ranking/` で申込数順の TOP リスト |
| 過去の月別ハイライトを振り返りたい | `/ranking/2024/9/` 等の月別ページ |
| 立ち上がったばかりのコミュニティを発見したい | `/recent_group/` |
| 自分のグループがどの程度規模を持つか比較したい | グループ詳細ページのメンバー数表示 |
| 外部メディア / レポートでランキングを引用 | 月別ランキングは過去スナップショットとして安定 URL |

Findy 関連レポート (Findy AI+, ファインディ / Findy グループ等) は connpass 上で **オーガナイザとしてイベントを開催している** 立場であり、connpass のランキング機能自体は Findy 独自のスコアではない (Findy 自社のスキル偏差値とは別物)。

## 3. 関連エンティティ・フィールド

### 3.1 イベントランキング (推定)

```
EventRanking
├─ period: enum {current, monthly}
├─ year, month
├─ entries: [Entry]
│   ├─ rank
│   ├─ event_id
│   ├─ accepted_count: integer (確定参加者数)
│   ├─ capacity: integer
│   ├─ application_count: integer (申込み総数、補欠含む)
│   ├─ organizer_group_id
│   └─ score: computed (= 申込数 or 確定参加者数 等)
└─ updated_at
```

### 3.2 グループ系

```
Group
├─ subdomain
├─ member_count: integer
├─ event_count: integer
├─ created_at
└─ ranking_position: computed (バッチで計算、参考値)
```

### 3.3 ユーザー側

公式には個人ポイント・バッジは未確認。プロフィールページには以下の「実績」が表示されるが、それは数値スコアではなくリスト形式:

- 参加したイベント
- 主催したイベント
- 発表したイベント
- ブックマークしたイベント

## 4. UI 上の入口と画面

### 4.1 イベントランキング

- グローバルヘッダの「ランキング」リンク (またはフッタ)
- `/ranking/` でカレントランキング
- `/ranking/YYYY/M/` で月別アーカイブ
- 表示項目: 順位、イベント名、開催日、主催グループ、申込数 / 定員、会場

### 4.2 新着グループ

- `/recent_group/`
- 表示項目: グループ名、公開日、メンバー数、管理者アイコン

### 4.3 グループ詳細

- グループページ右側に「メンバー数 / イベント数」が表示される
- メンバー数の月次推移グラフは公式機能としては未確認 (主催者向けの統計画面でイベント単位の閲覧数等は提供)

## 5. 外部サービス連携

ランキング機能は connpass 内部完結で、外部サービス連携は基本的にない。ただし:

- **Findy のレポート**: Findy が独自に connpass API + 自社データを集計して「人気エンジニアコミュニティ Top X」等を発表することがある。これは Findy 側の独自スコアで、connpass の公式機能ではない。
- **公開 API**: `/api/v2/events/` で `accepted` や `limit` を取得できるため、第三者が独自ランキングを作成できる。

## 6. ルール・制約

- ランキングの算出ロジックは公式に詳細公開されていない。観察できる範囲では「申込数 (accepted + waitlist)」が主要シグナル。
- 月別ランキングは過去スナップショットとして URL 永続化されている。
- 個人ユーザーのスコア表示はない (= リーダーボード文化を意図的に避けている)。
- ランキングへの登場可否は主催者が個別にオプトアウトできない (= 全公開イベント自動対象)。
- 「メンバー数の絶対値」がそのまま評価されるとコミュニティの古さに有利になるため、connpass は **直近開催イベントの申込数** を重視している模様。

## 7. 模倣実装時の代替案

### 7.1 ランキング設計

単純な「申込数順」だけでは、巨大コミュニティが常時上位を占めて新参が浮上できない。模倣実装では、以下のような重み付けスコアを推奨:

```
score = log(application_count + 1) * recency_factor * (1 - duplicate_organizer_penalty)
recency_factor = exp(-age_days / 30)  # 新しいイベントを優遇
```

- 新規グループ向けの **「ライジング」枠** (前週比増加率) を別タブで提供。
- カテゴリ別 (AI / フロントエンド / セキュリティ / 学生向け 等) のサブランキング。

### 7.2 ユーザー向けスコア (差別化機能)

connpass にない「主催者ポイント」「参加者バッジ」を導入する場合の方針:

| 指標 | 計算ロジック | UI |
|------|---------------|------|
| 主催者貢献度 | 主催イベント数 × 平均参加者数 | プロフィールにバッジ |
| 登壇回数 | 「発表者」として登録された回数 | バッジ + リスト |
| 参加実績 | 過去 1 年の参加数 (連続参加月数) | ストリーク表示 |
| コミュニティ多様性 | 参加グループ数 | バッジ |

ただし、connpass が意図的に避けてきた領域でもあるため、**スコアは「自分にだけ見える」モードを default にする** など、競争を煽らない設計が望ましい。

### 7.3 グループランキング

- メンバー数 (絶対値) と直近半年のアクティビティ (イベント開催数・参加数) を組み合わせた複合スコア。
- 「メンバー獲得が早いグループ TOP10」「直近半年で最もイベント開催の多いグループ」等の切り口。

### 7.4 ランキングのアンチパターン回避

- 自前で N+1 の集計を毎リクエストで走らせない (バッチで日次集計 → キャッシュ表示)。
- 申込水増し対策: 短時間に大量の参加申込が同一 IP / fingerprint から発生した場合のスコア除外。
- 主催者の自演申込 (関係者だけで上位化) 対策: 主催者と所属メンバーの参加分はスコア重みを下げる。

### 7.5 外部 PR への活用

- 月次ランキングは「年末ベストイベント」「年間カンファレンス Top 10」などの形でブログ記事化すると PR 効果が高い。
- ランキング URL 永続化 (`/ranking/2026/06/`) は SEO 観点でも有効。

### 7.6 Findy 等の外部レポートとの位置付け

模倣実装する際は、「人気コミュニティランキング」を connpass のように公式機能として提供しつつ、外部の人事系サービス (Findy / LAPRAS / Forkwell 等) には API を通じて生データを提供できる構造にしておくと、第三者のコンテンツ化を促進できる。
