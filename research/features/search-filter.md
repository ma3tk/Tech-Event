# 検索・絞り込み機能 (Search & Filter)

connpass.com の検索・絞り込み機能 (キーワード、日付、エリア、タグ、オンライン/オフライン、参加費、定員等) を整理する。

---

## 1. 機能の目的とユーザーバリュー

### 目的
- 「いつ・どこで・何の・誰の」イベントなのかを多角的に絞り込み、希望に合うイベントを素早く発見できるようにする。
- 主催者にとっては「ターゲット層に届きやすくする」ためのインデックスでもある。
- API 経由で外部サイト・カレンダーへの埋め込みを促進する。

### ユーザーバリュー
- **参加者**: 興味分野・行ける地域・空いている日付の組み合わせで素早く絞れる。オンライン専用 / 対面専用の区別も明確。
- **主催者**: タグ・エリア・カテゴリを適切に設定することでターゲットに届きやすくなる。
- **外部開発者**: 公開検索 API で自分のサイトに勉強会一覧を埋め込み可能。

## 5. ルール・制約

### 5.1 キーワード検索
- title, catch, description を対象とする全文検索。
- 形態素解析ベース (MeCab + Kuromoji 等) または N-gram で日本語対応。
- AND 検索 (スペース区切りで複数語)。
- 表記ゆれ (全角/半角・カタカナ/ひらがな) を吸収する正規化を実装すると推測。

### 5.2 日付
- `date_from`, `date_to` の範囲指定。
- 「開催日」基準 (募集締切ではない)。
- どちらか片方のみでも可。
- 過去イベントは別タブ or 別フィルタで「終了済みも含む」を選択しないと表示されない (UX 上の判断)。

### 5.3 エリア
- 都道府県 47 + 「オンライン」の固定値。
- 住所欄に「オンライン」と書かれているイベントが「オンライン」検索でヒットする。
- 県名の正規化: ユーザー入力の住所欄から都道府県を抽出 (郵便番号 or 住所パース)。

### 5.4 並び順
- 「開催日昇順」「開催日降順」「新着順」(=作成日降順) の 3 種。
- デフォルトは「開催日昇順」(直近イベント優先)。

### 5.5 タグ
- タグは主催者が自由に設定するフリータグ + システム正規化タグの両立。
- タグ検索は AND (複数指定で絞り込み)。
- タグごとに専用ページ (`/tag/:tag_name/`) が存在し、関連イベント一覧を表示。

### 5.6 オンライン / オフライン
- 厳密な enum フィールドではなく、住所欄に「オンライン」と書かれているかで判定するという運用。
- 検索精度向上のため、内部では `online_flag` のような派生フィールドを持つと推測。

### 5.7 参加費
- 各参加枠の最小値・最大値を派生フィールドとして持つ。
- 「無料イベントのみ」フィルタは `fee_max == 0` で抽出。

### 5.8 ページング
- 1 ページあたり 50〜100 件。
- `start` パラメータでオフセット指定 (API)。

### 5.9 検索インデックス
- メイン DB とは別に Elasticsearch / OpenSearch / Solr を利用すると推測。
- インデックス更新はイベント作成・更新時にイベント駆動で同期。
- 削除イベント・下書きは検索対象外。

### 5.10 認可
- すべてのイベントは public (private 機能なし) のため、検索は誰でも実行可能 (ログイン不要)。

## 6. ユーザー視点のフロー

### 6.1 トップページからの検索
1. トップページのキーワード入力欄に語句を入れる。
2. 検索ボタン押下で `/search/?keyword=...` に遷移。
3. 結果一覧を確認。

### 6.2 高度な絞り込み
1. 検索結果画面のサイドバーで日付・エリア・並び順を選択。
2. URL が即座に更新され、結果が再描画。
3. ブックマーク可能。

### 6.3 タグから探す
1. イベント詳細のタグをクリック。
2. `/tag/:tag_name/` に遷移し、同タグの関連イベント一覧を閲覧。
3. さらにフィルタを追加して絞り込み可能。

### 6.4 主催者・グループから探す
1. 興味のある主催者ニックネームを検索。
2. 主催者プロフィールから過去・未来のイベントを閲覧。
3. グループページから過去イベントを閲覧。

### 6.5 ブックマーク
- 検索結果から気になるイベントをブックマーク。
- マイページから後で確認。

---

## 7. 主催者視点のフロー

### 7.1 検索ヒットさせるための準備
1. イベント作成時にタイトル・サブタイトル・タグを適切に設定。
2. 住所欄に「オンライン」を明記 (オンライン検索対象になるため)。
3. 都道府県を住所から抽出されるように正確な住所を入力。
4. 説明文に検索キーワードを自然に含める。

### 7.2 タグの戦略
- 関連するメジャータグを 3〜5 個追加。
- 過剰タグは推奨されない (SEO 観点)。

### 7.3 グループからの導線
- グループに紐づければ「グループフォロワー全員へ自動通知」されるため、検索以外の流入経路を確保。

## 9. エッジケース

| ケース | 挙動 |
|---|---|
| 検索結果 0 件 | 「該当するイベントはありません」表示、条件を緩めるリンク |
| キーワードが極端に長い | 一定長で切り捨て、または 400 エラー |
| 不正な日付範囲 (`date_to < date_from`) | サーバ側で正規化または UI で警告 |
| 「オンライン」と「東京都」の同時指定 | 両方を含む結果 (OR) or 「ハイブリッド」のみ (AND)、要設計判断。実装上は「オンライン OR 都道府県」が UX 的に自然 |
| タグ名に特殊文字 | URL エンコードして処理。`#C++` など記号含みも対応 |
| 削除イベント | インデックスから即時除外 |
| 公開→下書きに戻したイベント | インデックスから除外 |
| 抽選中 / 開催中 / 終了直後 | デフォルト検索は「開催前」のみだが、フィルタ追加で表示可能 |
| 大量タグ指定 | サーバ側で上限 (5 個程度)、超過は無視 |
| 同タイトル多数のイベント | スコアリングで主催者の評価・参加人数で並び替え |
| 主催者ニックネーム変更 | インデックスの更新タイミング次第で一時的に古い結果が出る |

## 10. 推測される内部処理

### 10.1 検索アーキテクチャ
```
[ユーザー入力] -> [API] -> [Elasticsearch クエリビルダ]
                              |
                              v
                       [Elasticsearch]
                              |
                              v
                       [結果 ID 取得]
                              |
                              v
                       [DB から詳細取得]
                              |
                              v
                       [結果カードとして返却]
```

### 10.2 インデックス更新
- イベント作成・更新時にドメインイベント `EventChanged` を発行。
- 非同期ジョブで Elasticsearch に upsert。
- 削除時は delete。

### 10.3 クエリ例 (Elasticsearch)
```json
{
  "query": {
    "bool": {
      "must": [
        { "multi_match": { "query": "Python", "fields": ["title^3", "catch^2", "description"] } }
      ],
      "filter": [
        { "range": { "started_at": { "gte": "2026-06-01", "lte": "2026-06-30" } } },
        { "term": { "prefecture": "東京都" } },
        { "terms": { "tags": ["Python", "AI"] } },
        { "term": { "status": "open" } }
      ]
    }
  },
  "sort": [{ "started_at": "asc" }],
  "from": 0,
  "size": 50
}
```

### 10.4 ファセット (集計)
- 検索結果と一緒に「都道府県別件数」「タグ別件数」「参加費別件数」を返すと UX が向上。
- Elasticsearch の aggregations を使用。

### 10.5 キャッシュ
- 人気の検索条件 (Top N) は短期間 (1〜5 分) キャッシュ。
- ファセット集計はクエリパラメータごとにキャッシュ。

### 10.6 都道府県正規化
- 住所文字列から「東京都」「神奈川県」等を抽出するライブラリ (例: `prefecture_parser`)。
- 「オンライン」キーワードを優先的に検出 (住所欄に含まれていれば online_flag = true)。

### 10.7 並び順の計算
- `date_asc / date_desc`: started_at ベース。
- `new`: created_at ベース。
- 検索スコア順は将来的に拡張 (推測)。

## 11. 模倣実装する際の設計案

### 11.1 検索 API
```
GET /api/events/search
  query:
    keyword: string
    date_from: date
    date_to: date
    prefecture: string (47都道府県 | 'online')
    tags: string[]
    fee: enum (free | paid)
    online: bool
    status: enum (open | closed | all)
    order: enum (date_asc | date_desc | new | popular)
    page: int
    per_page: int (max 100)

  response:
    {
      "total": number,
      "items": [Event...],
      "facets": {
        "prefecture": { "東京都": 120, "オンライン": 50 },
        "tags": { "Python": 30, "AI": 25 }
      }
    }
```

### 11.2 インデックス設計 (Elasticsearch)
```json
{
  "mappings": {
    "properties": {
      "title":      { "type": "text", "analyzer": "kuromoji" },
      "catch":      { "type": "text", "analyzer": "kuromoji" },
      "description":{ "type": "text", "analyzer": "kuromoji" },
      "started_at": { "type": "date" },
      "ended_at":   { "type": "date" },
      "prefecture": { "type": "keyword" },
      "online":     { "type": "boolean" },
      "fee_min":    { "type": "integer" },
      "fee_max":    { "type": "integer" },
      "capacity":   { "type": "integer" },
      "has_vacancy":{ "type": "boolean" },
      "tags":       { "type": "keyword" },
      "group_id":   { "type": "long" },
      "status":     { "type": "keyword" }
    }
  }
}
```

### 11.3 非同期インデックス更新
```python
@subscribe(DomainEvents.EVENT_PUBLISHED)
@subscribe(DomainEvents.EVENT_UPDATED)
def reindex(event):
    SearchIndexer.upsert(event.id)

@subscribe(DomainEvents.EVENT_DELETED)
def deindex(event):
    SearchIndexer.delete(event.id)
```

### 11.4 UX 上の工夫
- URL ステート同期 (React Router / Next.js でクエリパラメータ反映)。
- 検索条件の保存機能 (お気に入り検索)。
- アラート機能 (条件にマッチする新着イベントをメール通知)。

### 11.5 テスト観点
- 各フィルタの単独動作
- 複数フィルタの AND 動作
- 並び順の正確性
- ページングの境界 (最終ページ、空ページ)
- 全角・半角の正規化
- 過去イベントのデフォルト除外
- インデックス再構築の冪等性
- 大量データでのパフォーマンス (10 万件で 100ms 以内)
- 不正パラメータの 400 ハンドリング
