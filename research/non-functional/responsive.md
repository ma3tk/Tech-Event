# connpass のレスポンシブ・モバイル対応

connpass.com をデスクトップ・タブレット・モバイル幅で観察し、ブレークポイントとレイアウト変化を整理する。観察は公開ページ (トップ, 新着, グループ, ヘルプ) を対象。

---

## 1. 観察したレイアウト挙動

### 1.1 デスクトップ (1280px+)
- 中央寄せの max-width: 1080〜1200px
- 2 カラム (本文 + サイドバー)
- グリッドベースのイベントカードレイアウト (3 列)
- ヘッダーは検索ボックスが大きく展開
- フッターはマルチカラムリンクメニュー

### 1.2 タブレット (768〜1023px)
- 1 カラムに圧縮、サイドバーは下部へ
- イベントカードは 2 列
- ヘッダーの検索はアイコンに集約またはコンパクト化
- ハンバーガーメニュー化されない (主要リンク常時表示)

### 1.3 モバイル (〜767px)
- 単一カラム
- イベントカードは縦並び 1 列
- ヘッダーはハンバーガーメニュー化
- 申込ボタンは画面下部に固定 (sticky CTA)
- フッターはアコーディオン化

---

## 2. 推定ブレークポイント

connpass はおそらく以下のブレークポイントを採用:

```css
/* モバイルファースト */
/* ベース: 〜639px (モバイル) */

@media (min-width: 640px)  { /* sm: 大型モバイル */ }
@media (min-width: 768px)  { /* md: タブレット */ }
@media (min-width: 1024px) { /* lg: 小型デスクトップ */ }
@media (min-width: 1280px) { /* xl: 大型デスクトップ */ }
@media (min-width: 1536px) { /* 2xl: 超大型 */ }
```

業界標準 (Bootstrap, Tailwind) に近い区分。

### 3.3 イベント詳細

## 4. タッチ操作と UI

### 4.1 タップ領域
- 全インタラクティブ要素は最小 44×44px (Apple HIG)
- リンク間の隙間を十分に
- 「キャンセル」ボタンと「申込確定」ボタンを誤タップしない配置

### 4.2 タップフィードバック
- :active 状態で背景色変化
- 50ms 以内の視覚フィードバック

### 4.3 スワイプジェスチャ
- 横スワイプでタブ切替 (参加者 / 補欠 / コメント)
- 垂直スワイプは標準スクロール
- iOS の「戻る」スワイプを妨げない

### 4.4 ピンチズーム
- viewport meta で禁止しない (`user-scalable=yes`)
- アクセシビリティ観点で重要

---

## 5. ヘッダーのモバイル化

### 5.1 ハンバーガーメニュー
- 左上または右上に三本線アイコン
- タップで drawer 表示
- メインリンク:
  - イベント検索
  - イベント管理
  - グループ作成
  - マイページ
  - ヘルプ
  - ログアウト

### 5.2 検索バー
- モバイルでは虫眼鏡アイコンに集約
- タップでオーバーレイ全幅検索フォーム

### 5.3 ロゴ
- 小サイズに圧縮
- タップでトップへ

---

## 6. フッターのモバイル化

- リンクをカテゴリごとにアコーディオン化
- SNS アイコンは横並びで中央寄せ
- 著作権表記とプライバシーリンクは下部固定

---

## 7. ボタンとフォーム

### 7.1 申込ボタン
- モバイルでは画面下部に sticky 配置
- スクロールしても見える
- 状態によってラベル変化 (申込 / キャンセル / 補欠)

### 7.2 フォーム入力
- input width: 100%
- type 属性で適切なキーボード (email, tel, number)
- ラベルは入力の上 (横並びは狭い画面で破綻)

### 7.3 セレクトボックス
- ネイティブ select を使用 (OS のホイール UI 活用)
- カスタムドロップダウンは a11y リスクが高い

---

## 8. 画像のレスポンシブ

```html
<img
  src="/img/event/362879-w640.webp"
  srcset="/img/event/362879-w320.webp 320w,
          /img/event/362879-w640.webp 640w,
          /img/event/362879-w1200.webp 1200w"
  sizes="(max-width: 640px) 100vw,
         (max-width: 1024px) 50vw,
         33vw"
  width="640" height="360"
  loading="lazy"
  alt="..."
/>
```

- srcset でデバイス幅に応じた最適画像
- sizes で実際の表示サイズを宣言
- width / height で CLS 防止

---

## 9. グリッドレイアウト

CSS Grid を活用:

```css
.event-grid {
  display: grid;
  gap: 16px;
  grid-template-columns: repeat(auto-fill, minmax(280px, 1fr));
}

@media (min-width: 1280px) {
  .event-grid {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

auto-fill / minmax を使うことでブレークポイントなしに柔軟に折り返す。

## 10. タイポグラフィのスケール

- ベース: 16px
- 見出し: clamp(1.5rem, 2.5vw + 1rem, 2.5rem) で滑らかスケール
- 本文行間: 1.7 (日本語)
- リンクは下線維持 (タップ可能性の明示)

## 11. ナビゲーション (パンくず)

モバイルでは省略表示:
- 「< 戻る」だけ表示
- もしくは「グループ名 > イベント」のみ (左端の「connpass」を省略)

---

## 12. テーブルのモバイル化

参加者リスト (主催者画面):
- デスクトップ: テーブル表示
- モバイル: カード型に変換 (1 行 = 1 カード)

例:
```
[アバター] 山田太郎
@yamada
参加 / 出席済み
東京都 / 山田太郎@example.com
[操作 ▼]
```

---

## 13. フォーム入力 (モバイルでの主催者)

- イベント作成フォームはモバイルでも可能だが、長大なので段階表示推奨
- ステップ式 (ウィザード) で「基本 → 開催情報 → 参加枠 → 詳細 → 確認」
- 各ステップで保存可能 (途中離脱に強い)

---

## 14. 通知の表示

- トースト通知: 画面上部中央 or 下部
- モバイルでは下部 (親指から近い)
- 自動消滅 5 秒、手動で閉じるボタン
- スワイプで dismiss

---

## 15. パフォーマンスとモバイル

モバイル環境は低帯域 / 低スペック端末を想定:

- 初期 HTML をできるだけ軽く (50KB 以下)
- JS バンドルは差分配信 (Polyfill は必要なときだけ)
- 画像は AVIF / WebP に優先配信
- フォントはサブセット化

---

## 16. オフライン対応

Service Worker による最低限のオフライン体験:
- 最近見たイベントをキャッシュ
- ブックマーク済みイベントの参照
- オフライン時の UI は「インターネット接続を確認してください」を明示

---

## 17. デバイス特有の対応

### 17.1 iOS Safari
- safe-area-inset (ノッチ対応)
- バウンススクロール対策
- date input の挙動差

### 17.2 Android Chrome
- ステータスバー色 (theme-color メタタグ)
- 戻るボタンの挙動 (Histroy API)
- WebShare API 対応

### 17.3 PWA
- manifest.json でホーム画面追加対応
- アイコン (Maskable Icon)
- スプラッシュ画面
- ショートカット (申込中のイベント、ブックマーク)

---

## 18. ダークモード

- prefers-color-scheme: dark で自動切替
- 設定 UI で手動切替も提供
- 画像のコントラストを暗背景でも維持

---

## 19. アクセシビリティとレスポンシブの重なり

- フォーカスインジケータはモバイルでも視認しやすく
- ハンバーガーメニューに aria-expanded / aria-controls
- モバイルでも 200% ズーム時に横スクロールが発生しないこと

---

## 20. テスト方針

### 20.1 デバイス実機テスト
- iPhone (Safari): 標準モデル + Pro Max
- Android (Chrome): Pixel, Galaxy
- iPad (Safari): 縦横両方
- デスクトップ: Chrome, Firefox, Safari, Edge

### 20.2 ブラウザ自動テスト
- Playwright で 4 サイズ (360, 768, 1024, 1440) でスクリーンショット差分
- Chromatic でビジュアルリグレッション

### 20.3 ネットワーク
- Slow 3G, Fast 3G, 4G でのテスト
- Lighthouse モバイル設定で計測

## 22. メディアクエリの書き方

モバイルファースト原則:

```css
/* ベース: モバイル */
.event-card {
  width: 100%;
}

/* タブレット以上 */
@media (min-width: 768px) {
  .event-card {
    width: calc(50% - 8px);
  }
}

/* デスクトップ以上 */
@media (min-width: 1024px) {
  .event-card {
    width: calc(33.333% - 11px);
  }
}
```

---

## 23. コンテナクエリ

将来的にコンテナクエリ (`@container`) を活用すると、サイドバー幅に応じてカード内レイアウトを柔軟化できる:

```css
.card-container {
  container-type: inline-size;
}

@container (min-width: 400px) {
  .card-content {
    display: grid;
    grid-template-columns: 120px 1fr;
  }
}
```

---

## 24. アンチパターン

- viewport-fit=cover でノッチ無視
- font-size: 14px 固定 (相対単位を使うべき)
- メディアクエリの分散 (CSS 変数で一元管理)
- ハンバーガーメニュー前提のナビゲーション (タブレット幅で破綻)
- 横スクロールテーブルをタップで気づかせない

## 25. 改善ロードマップ

1. **Phase 1**: モバイルファースト CSS への移行、ブレークポイント統一
2. **Phase 2**: 申込ボタン sticky CTA, ハンバーガーメニュー改善
3. **Phase 3**: 画像 srcset 全面適用, 主要ページの Lighthouse Mobile 90+
4. **Phase 4**: PWA 化 (manifest, SW)
5. **Phase 5**: コンテナクエリ採用、フレックス &グリッドの最適化
6. **Phase 6**: ダークモード対応、デバイス別ビジュアルリグレッションテスト

## 26. 計測

- Real User Monitoring (RUM) でデバイス別パフォーマンス追跡
- ビューポートサイズ分布 (Google Analytics)
- タップエラー率 (Hotjar / FullStory)
- モバイル CVR vs デスクトップ CVR

これらを継続的に計測することで、モバイル体験の改善が定量化できる。
