# connpass のセキュリティと個人情報保護

connpass.com のプライバシーポリシー観察と利用規約 / FAQ からの考察、および IT イベント支援プラットフォームとして求められるセキュリティ・プライバシー要件を整理する。

---

## 1. 個人情報の収集項目 (observed)

プライバシーポリシーより、connpass が収集する情報:

### 1.1 ユーザー入力
- メールアドレス
- 氏名 (任意)
- 所属組織
- 自己紹介
- アバター画像
- ニックネーム (公開)
- 居住地

### 1.2 自動収集
- 端末識別子 (Cookie, デバイス ID)
- アクセスログ (IP, User-Agent, リファラ)
- 閲覧履歴
- ブラウジング行動

### 1.3 連携 SNS から
- X (Twitter): アカウント名、表示名、メール
- Facebook: 同上
- GitHub: 同上
- PayPal: 決済情報

## 3. 公開範囲の設計

connpass はオープンコミュニティ思想のため、デフォルトの公開度が高い。

| 情報 | デフォルト公開 | 設定で変更可 |
|---|---|---|
| ニックネーム | 公開 (URL に使用) | 不可 (再登録のみ) |
| 表示名 | 公開 | 可 |
| アバター | 公開 | 可 |
| 所属組織 | 任意公開 | 可 |
| 自己紹介 | 任意公開 | 可 |
| メールアドレス | 非公開 | - |
| 参加イベント履歴 | 公開 (プロフィール) | 一部削除可 (FAQ「参加履歴を削除」) |
| 申込中のイベント | 一覧公開 | - |
| 出席履歴 | 公開 | 一部削除可 |
| グループ所属 | 公開 | - |
| ブックマーク | 非公開 | - |

参加者にとって「参加履歴がポートフォリオになる」というプラス面と「過去の参加実績を消したい」というプライバシー要望のバランス調整。

## 4. 認証セキュリティ

### 4.1 パスワード
- 推奨: 8 文字以上、英数字混合
- ハッシュ化: bcrypt / Argon2 (cost 12 以上)
- パスワードリセットはメール経由のワンタイムトークン (有効期限 1 時間)
- FAQ「パスワードを忘れた」の項目あり

### 4.2 二要素認証 (2FA)
- 現状 connpass の 2FA は非対応の可能性
- 推奨: TOTP (Google Authenticator) と SMS の両方を提供
- バックアップコードの発行

### 4.3 ソーシャルログイン
- OAuth 2.0 / OpenID Connect 準拠
- アクセストークン / リフレッシュトークンの暗号化保管
- スコープ最小化 (必要最低限の権限のみ要求)

### 4.4 セッション
- HTTP-only, Secure, SameSite=Lax の Cookie
- セッションタイムアウト: 30 日 (Remember Me)、ブラウザ閉じで失効するオプション
- 同時セッション数の上限 + アクティブセッション一覧の提供

## 5. メール検証

メール検証は単なるアカウント検証以上の意味を持つ:

- 主催者からの重要通知 (会場変更、キャンセル) の到達保証
- 不正アカウント大量作成の抑止
- 抽選結果メールの到達

未検証ユーザーは申込不可。

---

## 6. 不正対策

### 6.1 申込の不正
- **重複申込**: 同一ユーザーの重複申込はデフォルト不可。allow_duplicate_join=true でも 1 イベント 1 ユーザー
- **botによる大量申込**: reCAPTCHA / Turnstile を申込フォームに導入。短時間連続申込は IP / fingerprint で検知
- **転売目的の申込**: 出席チェックを QR ベースにし、第三者への譲渡を制限

### 6.2 主催者の不正
- **架空イベント**: 開催実績ゼロのアカウントは申込警告
- **詐欺イベント**: ユーザー通報フォーム、運営審査
- **個人情報の悪用**: CSV エクスポートのログ記録

### 6.3 アカウント乗っ取り
- 通常と異なる IP / 端末からのログインを検知 → メール通知
- 連続ログイン失敗で一時ロック (15 分)
- パスワード変更時に旧パスワード入力必須

### 6.4 ブラックリスト
- グループ単位で `GroupBlacklist` を運用
- 全グループでの BAN は運営判断 (User.status=suspended)

---

## 7. 決済セキュリティ

### 7.1 PCI DSS 準拠
- カード情報を直接保持しない (PayPal にリダイレクト)
- トランザクション ID と決済結果のみ自前 DB に保管

### 7.2 PayPal 連携
- Webhook で決済結果を受信
- 署名検証 (PayPal の証明書ベース)
- 冪等処理 (同一 trans_id の重複受信を 1 件として処理)

### 7.3 返金
- 主催者操作 / 運営仲裁による返金
- 監査ログに記録

---

## 8. データ暗号化

### 8.1 通信
- 全通信 HTTPS (HSTS preload 登録)
- TLS 1.3 を最優先
- 古い TLS (1.0/1.1) は廃止

### 8.2 保存時
- データベース: PostgreSQL の透過的暗号化 (TDE) または列レベル暗号化
- 機密フィールド (passwordHash, oauthTokens, payment.provider_txn_id) は AES-256-GCM
- バックアップは暗号化された S3 バケット

---

## 9. アクセス制御

### 9.1 ロール (RBAC)
- ユーザー (一般)
- グループ管理者 (admin / owner)
- イベント管理者
- 運営スタッフ (内部 / カスタマーサポート)
- システム管理者

### 9.2 監査
- 重要操作 (BAN, 強制キャンセル, データ閲覧) は AuditLog に記録
- 管理画面アクセスは IP allowlist + 2FA 必須

### 9.3 最小権限
- スタッフは業務に必要な最小限のデータのみアクセス可能
- 退職時に即座に権限剥奪

---

## 10. 退会と削除

### 10.1 ユーザー退会
- マイページから退会申請
- ニックネーム / 表示名 / アバターを「退会ユーザー」に置換
- メールアドレス / 個人情報を破棄
- 参加履歴は「退会ユーザー」として残る (主催者側の名簿維持のため)

### 10.2 完全削除請求
- プライバシーポリシーに基づく削除請求は運営窓口 (info@connpass.com)
- 法的保持義務 (税務、紛争対応) の範囲内で対応

### 10.3 グループ削除
- メンバー / イベントがあるグループは原則削除不可
- 運営申請による例外対応

---

## 11. クッキー

- 必須クッキー (セッション、CSRF トークン) は同意なしで設定
- 計測クッキー (Analytics) は同意取得後
- バナーで明示的同意 + 詳細設定リンク
- EU 訪問者にも対応する Cookie 同意 UI

---

## 12. CSRF / XSS 対策

### 12.1 CSRF
- POST / PUT / DELETE には CSRF トークン必須
- SameSite=Lax で多くは防御
- Origin / Referer ヘッダ検証

### 12.2 XSS
- ユーザー入力 (description, comment.body) は Markdown レンダリング時にホワイトリストサニタイズ
- DOMPurify などのライブラリ採用
- CSP (Content-Security-Policy) ヘッダで script-src を制限

### 12.3 SQL Injection
- Prisma の prepared statement で防止
- 生 SQL を使う箇所はパラメータバインド徹底

### 12.4 Open Redirect
- `?next=...` パラメータは内部パスのみ許可

## 13. レート制限

| エンドポイント | レート上限 |
|---|---|
| ログインフォーム | 5 req/min/IP |
| 新規登録 | 3 req/min/IP |
| 申込ボタン | 10 req/min/user |
| API (公開) | 60 req/min/IP |
| メール検証再送 | 3 req/hour/email |
| 主催者の一斉メッセージ | 5 req/day/group |

これにより DoS や不正大量送信を抑制。

---

## 14. メール配信のセキュリティ

- DMARC / SPF / DKIM の設定
- なりすましメールへの対応 (報告窓口)
- 配信停止リンクは認証トークン付き URL

---

## 15. インシデント対応

### 15.1 体制
- セキュリティ責任者 (CISO 相当)
- インシデント対応プレイブック
- 24h 連絡可能なオンコール

### 15.2 通知
- 重大インシデント発生時は 72 時間以内に当局・ユーザーに通知 (GDPR 準拠の精神で)
- ステータスページの提供

### 15.3 復旧
- バックアップは日次 + 増分
- リストア訓練を四半期ごとに実施

## 16. プライバシー設定 UI

ユーザーがプライバシーレベルを管理できる UI を提供:

```
[マイページ > プライバシー設定]
  ├ プロフィール公開
  │   - 表示名: 公開 / 非公開
  │   - 自己紹介: 公開 / 非公開
  │   - 所属: 公開 / 非公開
  ├ 参加履歴
  │   - 全イベント: 公開 / 非公開
  │   - 過去 1 年のみ公開
  │   - イベント別に個別非公開
  ├ メール通知
  │   - イベント情報 (グループ告知)
  │   - リマインダー
  │   - レコメンド
  ├ データダウンロード
  │   - 自分のデータを zip でダウンロード
  └ アカウント
      - パスワード変更
      - 2FA 設定
      - 退会
```

| メール確認トークン | 24 時間 |

## 18. 第三者提供

connpass は基本的に第三者提供しない方針 (プライバシーポリシー)。ただし以下は例外:

- 決済処理 (PayPal)
- メール配信 (SendGrid 等の SaaS)
- アクセス解析 (Google Analytics 等)
- 司法・行政の要請

すべてプライバシーポリシーで明示。

---

## 19. 主催者責務 (CSV エクスポートの扱い)

connpass の特性として、主催者は参加者リスト (氏名・メアド) を CSV エクスポート可能。これにより以下のリスクと責務が発生:

- 主催者は個人情報取扱事業者として法的義務を負う
- connpass はエクスポート時に「個人情報の適切な取り扱い」を警告表示すべき
- CSV エクスポート操作を AuditLog に記録し、必要に応じユーザーに通知

- [ ] プライバシーポリシーが最新で日本語と英語両方ある

- [ ] 退会フローが提供されている
