## 1. 概要・目的

イベント詳細ページは、ある1つのイベントに関する**完全な意思決定情報**を提供することを目的とする。具体的には:

1. **意思決定支援**: 日時/場所/費用/対象/内容を把握し、参加可否を判断できる。
2. **申込導線**: 「申し込む」「キャンセル」「キャンセル待ち登録」「外部フォームへ誘導」など、参加アクションを最短で実行。
3. **コミュニティ可視化**: 参加者一覧、ハッシュタグ、コメント、フィードを通じて雰囲気を伝える。
4. **共有**: SNS シェアでイベントを拡散する起点となる。
5. **当日運営**: 開始2時間前に参加リンク配布、出席確認 (受付票) などのオペレーションを支える。
6. **情報源 (アーカイブ)**: 開催後は資料公開・登壇者プロフィール・タイムテーブルがリファレンスとして残る。

## 2. URL構造とパスパターン

### 2.1 主URL

| パターン | 説明 |
| --- | --- |
| `https://{group}.connpass.com/event/{event_id}/` | 正規URL。`group` はグループのスラッグ |
| `https://connpass.com/event/{event_id}/` | グループサブドメインへの 302 リダイレクト元 |
| `…/event/{id}/presentation/` | 資料投稿一覧 |
| `…/event/{id}/participation/` | 参加管理 (主催者用) |
| `…/event/{id}/participation/?status=accepted` | 参加者一覧の状態フィルタ |
| `…/event/{id}/participation_table/` | 参加者表 (主催者向け) |
| `…/event/{id}/feed/` | コメント/フィード API or Atom |
| `…/event/{id}/ical/` | iCalendar (.ics) ファイル |
| `…/event/{id}/google_calendar/` | Google カレンダー登録リンク |
| `…/event/{id}/print/` | 受付票印刷 |
| `…/event/{id}/edit/` | 編集 (主催者) |
| `…/event/{id}/cancel/` | キャンセル (参加者) |
| `…/event/{id}/manage/` | 当日運営ダッシュボード (推測) |

### 2.2 クエリパラメータ

| パラメータ | 用途 |
| --- | --- |
| `?from=feed` 等 | 流入元計測 |
| `?ptype_id=N` | 参加枠別の動線 |
| `?utm_*` | 外部広告計測 |

### 2.3 Subdomain の意義

`{group_slug}.connpass.com` は、グループ専用の独立サイト的な扱い。SEOではサブドメインごとに評価が分かれる構造。

### 6.1 ユーザーロール別

| 役割 | 申込ボックス | 参加者リスト | コメント | 編集系 |
| --- | --- | --- | --- | --- |
| 未ログイン | "申し込むにはログインしてください" → `/login` | 公開状態に従い表示 | ログイン要求 | 非表示 |
| ログイン (未申込) | "申し込む" 押下 → 規約モーダル → 申込 | 表示 | 投稿可 | 非表示 |
| ログイン (申込済) | "キャンセル" or "参加情報" | 表示 | 投稿可 | 非表示 |
| ログイン (補欠) | "キャンセル待ち" バッジ + 優先繰り上がり通知設定 | 表示 | 投稿可 | 非表示 |
| 主催者 | 編集/管理/メッセージ/受付ダッシュボードの導線 | 全員表示 + 出席チェック | 主催者として固定投稿可 | 表示 |
| 共同管理者 | 主催者と同等 (権限内) | 同上 | 同上 | 表示 |

### 6.2 イベントステータス別

| ステータス | 主要表示 | CTA |
| --- | --- | --- |
| 受付開始前 | 「受付開始: YYYY/MM/DD HH:MM」のカウントダウン | 「申込開始通知を受け取る」(任意機能) |
| 受付中 | 各枠の進捗 | 「申し込む」「キャンセル待ち登録」 |
| 満員 | 「満員」バッジ、補欠枠の状況 | 「キャンセル待ちに登録」 |
| 受付終了 | 「受付終了しました」 | 申込不可 |
| 開催中 | 「開催中」 + 参加リンク (申込者のみ) | 「参加リンクを開く」 |
| 終了 | 「終了」グレーアウト | 資料閲覧、ハッシュタグ |
| 中止 | 赤バッジ + 主催者からの案内 | 申込不可 |

### 6.3 申込手段別

- **connpass内申込**: ボタンで直接申し込み。
- **外部フォーム (Googleフォーム等)**: 「申込フォームへ」ボタンで外部遷移。connpass の参加者リストには反映されない場合がある。
- **事前決済 (PayPal)**: 申込時に決済フロー。手数料は最安値訴求。

## 7. インタラクション

- **申し込むボタン**: 押下で確認モーダル → API リクエスト → 成功時に状態書き換え (CTA がキャンセルに変化、参加者リストに自分が追加)。
- **キャンセル**: モーダルで理由入力 (任意) → 削除確定。
- **参加者リスト「もっと見る」**: モーダル or 別ページ (`/participation/`) に遷移。
- **Map**: マウスホイールでズーム、ピンクリックで吹き出し。モバイルでは指タッチ。
- **タイムテーブル**: 横スクロール対応 (モバイル)。
- **シェアボタン**: 新規ウィンドウで SNS シェア URL を開く (`window.open` + `noopener`)。
- **カレンダー追加**: Google はディープリンク、.icsはダウンロード。
- **ハッシュタグクリック**: X 検索結果ページへ遷移 (`https://x.com/search?q=%23xxx`)。
- **コメント投稿**: フォーム → API POST → DOM 追加。Markdown プレビュー対応の余地。
- **スクロール**: サイドバー申込ボックスは `position: sticky` (デスクトップ)、モバイルでは下部固定 (`position: fixed`) の CTA バー化が定番。
- **画像クリック**: 拡大表示 (Lightbox) の余地。

## 8. 推測されるAPIコール

### 8.1 詳細取得

```
GET /api/v1/event/{event_id}/
```

レスポンスに含まれる主項目: `title`, `catch`, `description`, `started_at`, `ended_at`, `limit`, `accepted`, `waiting`, `address`, `place`, `lat`, `lon`, `event_url`, `series`, `owner`, `hash_tag`, `ticket_types`, `presenters`.

### 8.2 参加者一覧

```
GET /api/v1/event/{event_id}/participants/?status=accepted|waiting|cancelled
```

ページネーション付き。

### 8.3 申込/キャンセル

```
POST /api/v1/event/{event_id}/participate/
DELETE /api/v1/event/{event_id}/participate/
```

ボディ: `{ ticket_type_id, answers: [...] }`。

### 8.4 アンケート

```
GET /api/v1/event/{event_id}/questionnaire/
POST /api/v1/event/{event_id}/questionnaire/answer/
```

### 8.5 コメント / フィード

```
GET /api/v1/event/{event_id}/comments/
POST /api/v1/event/{event_id}/comments/
```

### 8.6 資料

```
GET /api/v1/event/{event_id}/presentations/
POST /api/v1/event/{event_id}/presentations/
```

### 8.7 主催者 (管理系)

```
PUT /api/v1/event/{event_id}/
POST /api/v1/event/{event_id}/announcement/

### 8.8 認証ユーザー固有

```

### 8.9 メタ情報

## 10. SEOメタ情報

サンプル観察値:

- `<title>`: 「{イベント名} - connpass」
- `<meta name="description">`: 概要文の先頭 ~120文字
- `<link rel="canonical" href="https://{group}.connpass.com/event/{id}/">`
- `<meta property="og:type" content="event">` (推奨; 実際は `article` の可能性)
- `<meta property="og:title">`, `<meta property="og:description">`, `<meta property="og:image">` (イベントカバー画像)
- `<meta name="twitter:card" content="summary_large_image">`
- 構造化データ JSON-LD: `Event` schema
  - `name`, `startDate`, `endDate`, `eventStatus`, `eventAttendanceMode` (Online/Offline/Mixed), `location`, `organizer`, `offers` (価格), `image`, `description`, `performer` (登壇者)
- `<link rel="alternate" type="application/atom+xml" href="…/event/{id}/feed/">` (推測)
- 日本語ロケール固定 `<html lang="ja">`

模倣する場合、Google の "Event 検索結果" 強化のため Schema.org Event を必ず実装する。`eventStatus` を `EventScheduled / EventCancelled / EventPostponed` で正しく更新するとリッチリザルトに有利。

## 11. レスポンシブ対応

- デスクトップ (≥1024px): 2カラム (メイン + サイドバー固定)。
- タブレット (768–1023px): 1カラム、申込ボックスはメインの上に挿入。
- モバイル (<768px):
  - HERO 縦伸ばし、タイトルは2-3行折返し。
  - 申込ボックスはページ上部 + 画面下部の固定 CTA バー併用。
  - タイムテーブルは横スクロール可能 (`overflow-x: auto`)。
  - 参加者リストはアバター10名 + "全員見る"。
  - 共有ボタンは小型化。
- 印刷スタイル: 受付票印刷用に `@media print` で広告/サイドバーを非表示。

## 12. アクセシビリティ観点

- `<h1>` はイベントタイトルに1つ。配下は `<h2>` (概要/タイムテーブル/諸注意/etc)。
- 申込CTA は `<button>` か `<a role="button">`。disabled 時は `aria-disabled="true"`。
- 参加者数バッジ `12/50` は `aria-label="申込12人 定員50人 残席38人"` のように明示。
- Google Maps の `<iframe>` は `title="開催地の地図"` を付ける。
- 動画/Twitter埋め込みも `title` 必須。
- カラーコントラスト: ステータスバッジは AA。
- カウントダウン (受付開始まで) は `aria-live="polite"` で読み上げ。
- カレンダー追加ボタンに `aria-label="Google カレンダーに追加"`。
- スクリーンリーダー用に "申込状況" を `<section aria-labelledby="entry-status">` でラベル。
- フォーカス順序: ヘッダー → タイトル → 申込CTA → 概要 → タイムテーブル → 登壇者 → 諸注意 → 参加者 → コメント → フッター。
- モーダル (申込確認) は `role="dialog" aria-modal="true"` + 初期フォーカス管理 + Esc クローズ。

## 13. 模倣実装する際の留意点

1. **データモデルが本丸**: `Event`, `TicketType`, `Participant`, `Group`, `User`, `Comment`, `Presentation`, `Questionnaire` のエンティティ関係を最初に固める。
2. **ステータスマシン**: イベントは「下書き → 公開 → 受付中 → 満員 → 開催中 → 終了 → アーカイブ」と遷移する。明示的に状態を持つ。
3. **タイムゾーン**: 全データを UTC で持ち、表示時に JST 変換。サーバー側で `started_at`/`ended_at` を ISO8601 で保管。
4. **タイムテーブルのスキーマ化**: Markdown 自由記述ではなく、構造化された `TimetableSlot` (start/end/title/speaker_id) を別途持つと構造化データやリマインダ機能で活きる。
5. **登壇者プロフィール**: `Speaker` エンティティを `User` と分離して持つと、外部登壇者にも対応しやすい。
6. **参加枠 (TicketType)**: 「先着/抽選」「定員」「価格」「補欠数」「説明」を必ずモデル化。複数枠は本質。
7. **抽選ロジック**: 抽選方式の場合、申込締切時にバッチで抽選 → メール通知 → 結果反映、までを設計。
8. **アンケート**: 申込時に自由入力可能なフィールド (`Questionnaire`)。回答は CSV エクスポート想定。
9. **事前決済**: PayPal/Stripe 統合は MVP では Stripe Checkout が無難。connpass の "業界最安値" 訴求は手数料を抑えた実装によるもの。
10. **キャンセル時の補欠繰上げ**: イベント中の動的な状態変化。Webhook/Cron でハンドリング。
11. **当日運営**: QR コード受付、出席記録、リマインダーメールは別画面で実装。
12. **共有OGP生成**: 動的に OGP 画像を生成する (`@vercel/og` 等)。タイトル/サムネ/日時を埋める。
13. **コメント機能**: スパム対策 (キーワードフィルタ + reCAPTCHA)、Markdown 部分対応、メンション通知。
14. **モデレーション**: コメント/外部リンクのモデレーション機能 (主催者が削除可能)。
15. **外部フォーム連携**: 自前申込フローを使わない場合に「外部フォームURL」を入れられる柔軟性。
16. **メール通知**: 申込完了/キャンセル/リマインダー (24h前/2h前)/結果メール。
17. **iCal/.ics**: シンプルだが必須機能。RFC5545 準拠で生成。
18. **権限管理**: 主催者・共同管理者・参加者・補欠・未参加 で UI 差し替え。RBAC を明示設計。
19. **SEO**: イベントごとの canonical URL を必ず1つに統一 (`{group}.example.com/event/{id}/`)。
20. **アーカイブ**: 終了後の検索インデックス対象から外す/残すの判断ポイントを設計。
21. **法務**: 個人情報、利用規約、Code of Conduct 表示、PayPal 利用規約への準拠。
22. **A/Bテスト**: 申込CTAの文言・配置は CVR に直結。実験基盤を初期から仕込む。
23. **アクセシビリティ**: モーダルとフォーカス管理は実装漏れしやすい。E2E テストで担保。
24. **i18n**: 日付・通貨フォーマットを `Intl` API で。後の英語対応に備える。

## 14. 観察から見えた個別パターン

### 14.1 オンライン専用 (Findy / DCT_findy)

- 場所: "オンライン (Zoom 等)"
- 地図表示なし
- 参加リンクは開始2時間前にメール配布 (申込者のみ)
- カレンダー連携 (.ics, Google) で予定確保を支援
- ハッシュタグ運用が活発 (`#DCT_findy` 等)

### 14.2 オフライン会場 (Kaminashi CS テラコヤ)

- 住所明記 (郵便番号付き)
- Google Maps 連携 (地図埋め込み)
- 軽食/懇親会の有無を明記
- 申込フローが外部 Google フォーム
- 各社3名まで等の参加制限条件付き
- 緊急連絡先の記載

### 14.3 ハイブリッド (Findy AI+)

- 参加枠が「オフライン枠」「オンライン枠」と並列に存在
- 定員設定が枠単位 (例: オフライン 5/200, オンライン 41/1000)
- 同一イベントでチャンネルを分ける運用

### 14.4 抽選 + 先着の混在 (カラビナテクノロジー)

- 学生枠: 先着 0/12
- メンター枠: 抽選 0/3
- 単一イベント内で「抽選」と「先着」を同時に持つ柔軟性

これらの**多態性**を踏まえ、TicketType は十分汎用に設計する必要がある。
