# connpass イベント検索 / 一覧ページ調査メモ

調査日: 2026-06-04
対象URL:
- https://connpass.com/explore/ (新着イベント一覧)
- https://connpass.com/event/ (リダイレクト挙動を含む観察対象。実体は `/explore/` 系もしくはサブドメイン側へ遷移)
- https://connpass.com/ranking/ (関連: 人気ランキング)

備考: 検索系UIは未認証ユーザーにも開放されており、API側のクエリパラメータと密接に関係する。

---

## 1. 概要・目的

`/explore/` は connpass における「イベント探索」のメインハブで、用途別に次のような役割を持つ。

1. **新着のディスカバリー**: 公開されたばかりのイベントを時系列で並べ、ユーザーが「今このコミュニティで何が起きているか」を俯瞰できる。
2. **ナビゲーションハブ**: サイドバーから「直近開催」「ランキング」「カンファレンス特集」「カレンダー」「新着グループ」「新着発表者」など、別の探索軸へジャンプできる起点。
3. **検索/フィルタの土台**: ヘッダーの検索アイコンや URL クエリパラメータを通じて、キーワード・タグ・日付・地域などのフィルタを適用する。

`/event/` パスはイベント単体ページの上位パスで、トップレベルのインデックスとしてはほぼ機能していない (個別 `/event/{id}/` でアクセスされる)。

## 2. URL構造とパスパターン

### 2.1 主URL

| パターン | 説明 |
| --- | --- |
| `/explore/` | 新着順イベント一覧 (1ページ目) |
| `/explore/?page=N` | ページネーション。観測時は `page=1`〜`page=7` 程度まで存在 |
| `/explore/feed/` | Atomフィード (HTMLでは `<link rel="alternate">` で示唆) |
| `/event/` | (トップレベル) インデックスとしては機能薄。アクセスすると 404 もしくは `/explore/` 系へリダイレクトする観測あり |
| `/event/{event_id}/` | 個別イベント詳細 (グループサブドメインへ302) |
| `/ranking/` | 人気イベントランキング (関連ページ) |
| `/calendar/` | カレンダー表示 |
| `/search/?q=...` (推測) | 検索結果ページ。実装上は `/explore/?keyword=...` の可能性も |

### 2.2 クエリパラメータ (推測込み)

公開API `https://connpass.com/api/v1/event/` のクエリ仕様に近い設計と推測される:

| パラメータ | 型 | 例 | 用途 |
| --- | --- | --- | --- |
| `page` | int | `?page=2` | ページ番号 (1始まり) |
| `keyword` / `q` | string | `?keyword=python` | フリーワード検索 |
| `keyword_or` | string list | `?keyword_or=python+go` | OR検索 |
| `ym` / `ymd` | int | `?ymd=20260615` | 日付絞り込み |
| `start_date` / `end_date` | YYYY-MM-DD | `?start_date=2026-06-01&end_date=2026-06-30` | 日付範囲 |
| `series_id` | int | `?series_id=123` | グループID |
| `nickname` | string | `?nickname=alice` | 主催者ニックネーム |
| `owner_nickname` | string |  | 主催者で絞り込み |
| `prefecture` / `area` | string | `?prefecture=tokyo` | 都道府県 |
| `online` | bool | `?online=1` | オンライン限定 |
| `offline` | bool | `?offline=1` | オフライン限定 |
| `category` | string | `?category=ai` | カテゴリ |
| `tag` | string | `?tag=python` | タグ絞込 |
| `order` | enum | `?order=created_desc` / `started_desc` / `popular` | ソート順 |
| `count` | int | `?count=20` | 1ページ件数 |
| `format` | enum | `?format=json` / `atom` | API出力形式 |

> 注: HTML 側UIにこれら全てが露出しているわけではなく、検索オーバーレイ + URL直打ち + API向けの混在仕様と推測される。

### 2.3 関連サブパス

- `/explore/groups/` — 新着グループ
- `/explore/users/` — 新着発表者
- `/explore/popular/` — (推測) 人気イベント
- `/series/{slug}/` — カンファレンス特集
- `/ranking/?ym=YYYYMM` — 月次ランキング (`<<前へ` で過去月へ)

## 5. 配置されているUIコンポーネント

- **GlobalHeader / GlobalFooter** : トップと共通。
- **SideNavigation** : テキストリンクの縦リスト。アクティブ項目をハイライト。
- **EventListCard** : サムネ + メタ + タイトル + 説明 + 主催 + 場所 + 参加状況の横長カード。
- **Pagination** : 数字 + 前/次のリンク群。
- **SearchTriggerButton** : ヘッダー右の検索アイコン。クリックで検索フォーム展開。
- **SearchOverlay / SearchForm** (推測) :
  - キーワード `<input type="search">`
  - 日付ピッカー (`start_date`, `end_date`)
  - チェックボックス (オンライン/オフライン)
  - セレクト (都道府県, カテゴリ, ソート順)
  - 送信ボタン
- **TagChip / CategoryChip** : クリックで `?tag=xxx` への遷移。
- **EmptyState** : 該当0件時に「該当するイベントがありません」を表示する想定。

## 6. 状態 (Auth/Filter) による出し分け

| 状態 | カードの表示差分 | 検索フォーム | サイドナビ |
| --- | --- | --- | --- |
| 未ログイン | 基本情報のみ。「参加する」CTAは押下時に認証ページへ | 全パラメータ操作可 | 全リンク有効 |
| ログイン済み (参加者) | 自分が参加済みなら「申込済み」バッジ、補欠なら「補欠中」 | 「参加した/しなかった」絞込が追加される可能性 | "マイイベント" 等の追加メニューの可能性 |
| ログイン済み (主催) | 自分が主催したイベントは編集アイコン表示の可能性 | 「自分のグループのみ」フィルタ | "新規作成" 導線が強調 |
| 検索結果0件 | EmptyState 表示 | 適用中フィルタを一覧で見せる | 通常通り |
| 満員イベント | 「満員」バッジ + 「キャンセル待ち」表示 | - | - |
| 終了イベント | 「終了」グレーアウト | デフォルトでは非表示 (`?order=ended_desc` で表示) | - |

## 7. インタラクション

- **イベントカード hover**: シャドウ強調、タイトル下線、サムネ拡大の微アニメーション。
- **カードクリック**: カード全体がリンク領域。グループサブドメインの `/event/{id}/` に遷移。
- **タグチップクリック**: `/explore/?tag={tag}` に遷移してフィルタ適用。
- **ページネーション**: クリックで full-page navigation。スクロール位置はトップへリセット。
- **検索アイコンクリック**: オーバーレイで検索フォームを展開。フォーカスはキーワード入力にトラップ。
- **検索送信**: URL クエリを更新してリロード。SPA 化していれば History API で push。
- **キーボードショートカット**: `/` でフォーカス、`Esc` で閉じるが望ましい。
- **無限スクロール**: 採用していない (ページネーション型)。
- **スクロール固定**: サイドナビをデスクトップでは `position: sticky` にすると UX が高い。

## 10. SEOメタ情報

- `<title>`: `新着イベント一覧 - connpass`
- ページネーション時は `新着イベント一覧 - 2ページ目 - connpass` のように差分付け推奨 (現状の公式は同一の可能性)。
- `<meta name="description">`: 「IT勉強会・カンファレンスを横断的に検索できる」旨。
- `<link rel="canonical" href="https://connpass.com/explore/">` (page=1)
- ページ2以降: `?page=N` を canonical に含める/含めない設計を選択。重複コンテンツ回避なら `noindex,follow` も検討。
- `<link rel="prev"> / <link rel="next">` でページネーション関係をマーク (推奨)。
- `<link rel="alternate" type="application/atom+xml" href="/explore/feed/">`
- 構造化データ: `ItemList` を JSON-LD で各イベントを列挙する設計が SEO 効果高い。

## 11. レスポンシブ対応

- デスクトップ: 2カラム (サイドナビ + メイン)。
- タブレット: サイドナビをドロワー化、メインは1カラム。
- モバイル:
  - カードはサムネ上, テキスト下の縦組にレイアウト変更。
  - 日付バッジは左肩のフローティング。
  - サイドナビはハンバーガーまたはアコーディオン。
  - ページネーションは「前へ / 次へ」を大きくし、数字はスクロール式に。

タッチ操作で誤タップしないよう、カード内のタグチップは十分な間隔を確保する。

## 12. アクセシビリティ観点

- 各カードは `<article>` でラップ、`aria-labelledby` でタイトルを参照すると意味的に明瞭。
- カード全体をリンクにする場合、内側のタグチップなどネストされたリンクは `event.stopPropagation()` を使うか、`role="link"` の擬似リンク化で対応する必要がある。
- 参加者数表記 `0/45` は `aria-label="申込0人/定員45人"` 等で補強。
- ページネーション領域は `<nav aria-label="ページ送り">` でラベリング。
- ステータスバッジは色だけでなく文字でも表現済み (`開催前` 等) で良好。
- 検索オーバーレイは `role="dialog" aria-modal="true"` を付与し、フォーカスをトラップ。
- アクティブなフィルタは `<output>` または可視チップで一覧化し、削除 (×) ボタンに `aria-label="〜の絞り込みを解除"` を付ける。
- 画像は `alt` 属性で内容を説明 (例: `alt="Group Logo: Findy"`)。

## 13. 模倣実装する際の留意点

1. **検索とフィルタを最初から設計に組み込む**: イベント一覧の本質はディスカバリー。キーワード/日付/地域/オンラインオフライン/タグ の最低5軸は必須。
2. **URLステート同期**: フィルタを URL クエリに反映することでシェア・ブックマークが効くようにする。SPA でも `history.pushState` を活用。
3. **サーバーサイドレンダリング**: SEO のため、検索結果は SSR で初期描画。ユーザー操作後は CSR でフィルタリングするハイブリッドが良い。
4. **API設計**: クエリの増減に強い `?filter[k]=v` 形式または独立したクエリパラメータで設計。`page` + `count` (limit/offset) は必須。
5. **キャッシュ戦略**: 新着一覧は分単位の CDN キャッシュ + バリアントとして `page` をキャッシュキーに。
6. **空状態と読み込み中**: スケルトンUI、0件メッセージ、検索条件の提示を必ず実装する。
7. **タグ・カテゴリの正規化**: タグは内部で `slug` を持ち、URLに使う形式 (`/explore/?tag=python`) を統一。
8. **無限スクロール vs ページネーション**: 一覧の用途が「探す」中心なら通常ページネーション、「眺める」中心なら無限スクロール。connpass はページネーション派。模倣時はどちらが UX に合うか議論。
9. **計測**: クリックイベントに順位 (`rank`)、フィルタ条件のスナップショットを `data-*` 経由で計測ライブラリへ送る。
10. **アクセシビリティ**: フォーカス管理・スクリーンリーダー対応を MVP から組む。後追いはコスト高。
11. **API公開**: 自社で外部APIを公開する余地 (Atom や JSON) を視野に入れた設計が将来効く。
12. **国際化**: 日本語固定で良いが、`Accept-Language` ベースの未来対応のためにテンプレートは i18n フレンドリに書く。
13. **法務**: 検索ログ・閲覧ログをユーザー紐付けする場合、プライバシーポリシーに明記。
14. **同期画面**: 主催者向け管理一覧 (`/dashboard/events`) は別ページ扱いで設計する。

## 15. 未確認・追加調査が必要な事項

- 検索オーバーレイの正確なフォーム要素 (HTMLが動的レンダリングで取得しづらかった)。
- 「人気順」など `order` の選択肢が UI 上で公開されているか。
- 検索結果が0件のときの EmptyState。
- ログイン状態固有の "おすすめイベント" セクションの有無。
- iCalendar / Google Calendar の一括追加機能 (検索結果から)。
- アクセシビリティ的な aria-live 利用 (検索結果更新時)。

これらは追加で認証付き状態を含めた再調査が必要。
