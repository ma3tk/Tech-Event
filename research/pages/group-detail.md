# グループ詳細ページ

## 概要・目的

connpass の「グループ詳細ページ」は、特定のコミュニティ（例: BPStudy, Python mini Hack-a-thon, DevLOVE 等）の入口であり、そのコミュニティの活動・歴史・メンバー・イベント・アウトプット（資料）を集約表示する中核ハブである。本ページは以下の役割を担う。

- グループのブランドページとしての機能（カバー画像 / 説明 / 主催者）
- 過去・未来のイベント一覧を時系列で提示
- メンバー獲得導線（「メンバーになる」CTA）
- 通知 / メール設定の入り口
- 資料・成果物のアーカイブ
- 主催者向け管理導線（権限ある場合）
- 外部 SNS や公式サイトへの導線

参考に閲覧した実例:

- BPStudy（`https://bpstudy.connpass.com/`）: メンバー 6,093 人 / 過去イベント 356 件 / 資料 654 件 / 管理者 4 名
- Python mini Hack-a-thon（`https://pyhack.connpass.com/`）: メンバー 1,175 人 / 多数の定例
- DevLOVE（`https://devlove.connpass.com/`）: メンバー 478 人 / メイン nav に「イベント / メンバー / 資料」

## URL 構造

- グループ TOP: `https://{subdomain}.connpass.com/`
- イベント一覧: `https://{subdomain}.connpass.com/event/`
- 過去イベント: `https://{subdomain}.connpass.com/event/?status=ended`
- 開催前イベント: `https://{subdomain}.connpass.com/event/?status=open`
- メンバー一覧: `https://{subdomain}.connpass.com/participation/`
- 資料一覧: `https://{subdomain}.connpass.com/presentation/`
- メール設定（要ログイン）: `https://{subdomain}.connpass.com/member_settings/`
- グループ編集（要管理者権限）: `https://{subdomain}.connpass.com/edit/`
- RSS フィード: `https://{subdomain}.connpass.com/?format=atom`

サブドメイン `{subdomain}` はグループ作成時に確定し、以降変更不可。

### 表示されるイベントカードの内訳

各イベントカード（過去・未来共通）:

- 日付（曜日含む）
- ステータス（「開催前」「募集中」「終了」「中止」）
- タイトル
- 開催形式（オフライン / オンライン / ハイブリッド）
- 開催場所（地名 or 「オンライン」）
- 募集状況（「888/1270 人」）
- グループ名（サブドメイン横断時のみ）

## 配置されている UI コンポーネント

- カバーヘッダー（背景画像 + ロゴ + タイトル + CTA ボタン群）
- タブナビゲーション（イベント / メンバー / 資料）
- 「メンバーになる」ボタン（または「参加中」バッジ）
- 「メール通知設定」リンク
- シェア群（はてブ / Facebook / X）
- イベントカードリスト
- 「すべてのイベントを見る (N 件)」リンク
- 資料カード（サムネ + タイトル + 投稿者）
- メンバーアバターグリッド
- 管理者リスト（小さなプロフィールカード）
- 外部リンクリスト
- RSS/Atom リンク

## 状態による出し分け

- **未ログイン**:
  - 「メンバーになる」→ ログインへ誘導
  - 「メール通知設定」非表示 or ログインへ誘導
- **ログイン済 / 未参加**:
  - 「メンバーになる」CTA 強調
- **ログイン済 / 参加済 (一般メンバー)**:
  - 「参加中」バッジ + 「退会」リンク
  - 「メール通知設定」リンクが活性
- **ログイン済 / 管理者**:
  - 「グループを編集」「メンバー管理」「ブラックリスト」ボタン表示
  - 統計やメンバー追加 UI が解放
- **メンバー限定イベント**:
  - 非メンバーには概要のみ、申込ボタンが「メンバー限定」表記に
- **カバー画像未設定**: 背景色のみのヘッダーにフォールバック

## インタラクション

- 「メンバーになる」ボタン押下 → 確認モーダル → 通知設定モーダル → 参加確定
- タブ切替 (`/`, `/event/`, `/participation/`, `/presentation/`) でページ遷移 or in-place 更新
- 「全てのイベントを見る」で `/event/` へ
- イベントカード全体クリックでイベント詳細へ遷移
- 資料カードクリックで Speaker Deck / SlideShare / connpass 内詳細へ
- 外部リンクは新規タブ
- 管理者アイコンクリックでユーザープロフィールへ
- 「メール通知設定」で頻度（毎回 / ダイジェスト / オフ）を選択

## 推測される API コール

- `GET /api/v1/group/{group_id}/` — グループ基本情報
- `GET /api/v1/group/{group_id}/event/?status=open` — 開催前イベント
- `GET /api/v1/group/{group_id}/event/?status=ended&page=2` — 過去イベント
- `GET /api/v1/group/{group_id}/member/?page=1` — メンバー一覧
- `GET /api/v1/group/{group_id}/presentation/` — 資料
- `POST /api/v1/group/{group_id}/join/` — メンバーになる
- `DELETE /api/v1/group/{group_id}/join/` — 退会
- `PATCH /api/v1/group/{group_id}/notification/` — メール通知設定
- `GET /api/v1/group/{group_id}/admin/` — 管理者一覧

公開 API v1（`https://connpass.com/api/v1/event/`）はイベント検索が中心。グループは内部 API が多い。

## 模倣実装する際の留意点

- **サブドメイン設計**: グループごとにサブドメインを切り出すと SEO / ブランド面で強い反面、SSL 証明書（ワイルドカード）と DNS 管理コストが増える。Path ベース (`/g/{slug}/`) も検討余地
- **カバー画像と背景色**: 主催者がブランディングしやすいよう、画像と色の両方を許可。画像未設定時のフォールバック色が美しく見える設計が大事
- **メンバー数表示**: 大規模グループでは数千～数万人に達するため、リアルタイム集計ではなく非同期更新
- **退会者の扱い**: 単純削除ではなく退会履歴を残し、再加入時の挙動を制御
- **メール通知頻度**: 「毎イベント」「週次まとめ」「重要のみ」「オフ」の 4 段階程度を推奨
- **権限分離**: 管理者 / モデレータ / 一般メンバー / フォロワーで権限を細分化
- **ブラックリスト**: 参加禁止リストを内部で持ち、申込時に自動拒否
- **資料 / アウトプット集約**: Speaker Deck や YouTube 等の外部リンクを埋め込みで表示
- **キャッシュ戦略**: グループ TOP は読み取りが多いので CDN / エッジキャッシュを活用
- **SEO**: グループは長期的にトラフィックを生む。`Organization` schema.org を埋め込み、メンバー数や設立日をマークアップ
- **大規模グループのページング**: メンバー一覧、過去イベントは万単位になるため Cursor ベースのページング推奨
- **イベントカードの一貫性**: グループ詳細とサイト全体（探す / マイページ）でカード UI を共通化
- **検索エンジンへの公開範囲制御**: connpass は基本公開だが、模倣サービスでは noindex / login-required などをフラグで制御可能に
- **エクスポート機能**: RSS / iCal / CSV エクスポートをグループ運営者向けに用意
- **タイムゾーン**: 海外メンバーが多い場合、各ユーザーの設定タイムゾーンで日時を表示
- **アクセシビリティ**: アバターグリッドは alt 必須、ボタン CTA はキーボードナビ対応
- **モバイル UX**: タブナビとフローティング CTA（「メンバーになる」）を画面下に固定すると効果的

## サブページ詳細

### イベント一覧 (`/event/`)

- フィルタ: ステータス（開催前 / 終了 / 中止）、年度
- 並び順: 開催日降順 / 昇順
- ページネーション (1 ページ 20 件程度)
- 各カードはサイトトップやランキングと共通の UI

### メンバー一覧 (`/participation/`)

- アバターグリッド + 名前
- 参加日順 / 名前順切替
- 管理者は別セクションで先頭表示
- ページング
- メール通知設定リンク（本人のみ）
- 大規模グループでは数千件のため、検索 / フィルタが必要

### 資料一覧 (`/presentation/`)

- 資料サムネ + タイトル + 発表者 + 紐づくイベント
- 投稿日順
- 外部サービス（Speaker Deck, SlideShare, YouTube）への埋め込みリンク
- 検索（タイトル / 発表者）

### メンバー設定 (`/member_settings/`, 要ログイン)

- グループからの通知頻度
- 「グループから退会」アクション

## 管理者専用 UI（権限ある場合のみ）

- 「グループを編集」ボタン
- メンバー追加（CSV / TSV インポート: `名前, メールアドレス` 形式）
- メンバー一括削除（チェックボックス + 削除ボタン）
- ブラックリスト管理
- 通知一斉送信
- 統計（参加者属性、流入経路）
- イベント新規作成

## グループ参加時のフロー（推測）

1. 「メンバーになる」ボタン押下
2. 確認モーダル（プライバシー説明）
3. メール通知頻度の選択（毎回 / ダイジェスト / オフ）
4. 参加完了 → 「メール通知設定」リンクが活性化
5. 主催者にメール通知（任意設定）

## 退会時のフロー（推測）

1. メール通知設定ページから「退会」ボタン
2. 退会理由（任意）
3. 確認モーダル
4. 退会完了 → ユーザーの所属グループ一覧から消える

## グループのライフサイクル

- 作成 → メンバー集め → 定期イベント開催 → 休眠 → 復活 / 完全終了
- connpass は休眠グループも残し続けるため、過去アーカイブとして機能
- 休眠 1 年以上のグループは検索結果で下位表示する設計が望ましい

## グループ詳細ページのパフォーマンス

- ファーストビュー（カバー + 概要 + CTA）を SSR
- 過去イベント一覧、メンバー一覧は遅延読み込み
- CDN で静的アセット（アイコン、カバー画像）を配信
- ETag によるブラウザキャッシュ
- 大規模グループでもファーストビューは 1 秒以内が理想

## 補足: 外部連携

- 公式サイト URL: グループの主体（企業・コミュニティ）の自社ページ
- X (Twitter): 公式アカウント
- Facebook ページ
- Slack 招待リンク（Python mini Hack-a-thon の例）
- GitHub Organization（OSS コミュニティの場合）
- Discord（最近増加）

## 計測すべき指標

- 一覧→詳細の流入
- 「メンバーになる」CTA の押下率
- イベント詳細ページからの遡り訪問率
- メンバー獲得後の継続率（アクティブメンバー比）
- 通知メール開封率 / クリック率
- 退会率と退会理由
