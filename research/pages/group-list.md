# グループ一覧ページ

## 概要・目的

connpass のグループ一覧ページは、エンジニア・デザイナー・データサイエンティスト等のテックコミュニティを横断的に発見・探索できる導線。connpass はイベント単位の運用が中心だが、その背骨を支えているのが「グループ」というユニットであり、コミュニティの継続性・所属感・通知配信単位として機能する。本ページは以下を目的とする。

- 新規ユーザーが興味のあるコミュニティを発見できる
- 既存ユーザーが他のグループに横展開する
- グループ主催者にとっての露出先・流入経路となる
- カテゴリやキーワードからの探索を可能にする

connpass のグループは「すべて公開」が原則で、非公開グループは存在しない。したがって、グループ一覧は connpass のサービス透明性とコミュニティ発見性を支える最重要画面の一つとなる。

## URL 構造

- 新着グループ一覧: `https://connpass.com/explore/group/` （非公開のため 404 になるケースあり）
- 新着グループ（推測の別名）: `https://connpass.com/new_groups/`
- すべてのグループ: `https://connpass.com/groups/`
- カテゴリ別 (推測): `https://connpass.com/groups/?category={category_id}`
- キーワード検索: `https://connpass.com/groups/?q={keyword}`
- 並び順: `?order=member` / `?order=event` / `?order=new`
- ページネーション: `?page=2` または `?start=51`

参考: トップページ・新着イベントページ下部の「新着グループ」セクションに、グループアイコン＋公開日とともに 5 〜 10 件抜粋表示され、「新着グループ一覧」リンクから一覧ページへ遷移する構造になっている。

## 並び順・フィルタ

- **新着順** (デフォルト, `order=new`)
- **メンバー数順** (`order=member`)
- **イベント開催数順** (`order=event`)
- **直近イベントが近い順** (`order=upcoming`)
- **キーワード絞り込み** (グループ名 / 説明 / タグへのフリーワード)
- **カテゴリ絞り込み** (推測: Web / Python / 機械学習 / モバイル / インフラ / デザイン / その他)
- **エリア絞り込み** (推測: 東京 / 大阪 / 福岡 / オンライン / 全国)

## 配置されている UI コンポーネント

- ヘッダー検索バー（イベント / グループ切替タブ付き）
- 並び順タブ
- グループカード（サムネイル、タイトル、説明抜粋、統計）
- タグチップ
- ページネーション
- 「グループを作成する」CTA ボタン (ログイン時)
- 空状態 (`「条件に合うグループは見つかりませんでした」`)

## 状態による出し分け

- **未ログイン**: 「グループを作成する」CTA は「ログイン / 新規登録」に置換
- **ログイン済**: 既に参加しているグループには「参加中」バッジを表示
- **検索クエリあり**: タイトルが「"{q}" の検索結果」に変化
- **0 件ヒット**: 検索条件のリセット導線
- **新着タブ vs 人気タブ**: ソート順とラベルが変化

## インタラクション

- カードクリックでグループ詳細ページへ遷移
- 並び順タブ切替で `?order=...` 更新 (history.pushState)
- 検索バーで Enter / submit → ページ遷移またはフェッチ
- ページネーションで `?page=...` 遷移
- 「メンバーになる」「フォロー」が一覧から直接押せるパターン（ログイン時）
- スクロール時の遅延読み込み（infinite scroll）の可能性

## 推測される API コール

- `GET /api/v1/group/?order=new&page=1` — グループ一覧取得
- `GET /api/v1/group/?q=python` — 検索
- `GET /api/v1/group/category/` — カテゴリマスタ
- `GET /api/v1/group/tag/` — タグマスタ
- `POST /api/v1/group/{group_id}/follow/` — フォロー（ログイン時）

connpass の公式 API v1（イベント検索 API）は存在するが、グループ専用の公開 API は限定的。内部 SSR + 部分的 XHR が主流と思われる。

## 模倣実装する際の留意点

- **発見性の最大化**: 単に「新着順」を並べるだけでなく、ユーザーの興味（過去参加イベント、所属タグ）に基づいたパーソナライズが効果的
- **タグ / カテゴリ設計**: 自由タグだけだと表記揺れ（「機械学習」「ML」「Machine Learning」）が起きる。マスタ管理推奨
- **メンバー数の更新タイミング**: リアルタイムでなくバッチ集計でも UX に支障ない（負荷低減）
- **新規グループの可視性**: 新着ロット枠を別に設けることで作りたて主催者のモチベ維持
- **検索精度**: グループ名と説明本文への全文検索インデックス必須
- **ボット・スパム対策**: 自動作成された空グループのフィルタ（メンバー 1 名、イベント 0 件の長期放置）
- **アクセシビリティ**: カード全体クリック領域、フォーカスインジケータ
- **SEO**: 一覧ページはクローラ重要。サーバサイドレンダリング + 構造化データ (`ItemList`, `Organization`)
- **OGP / シェア**: カテゴリページ単位でシェア対応
- **「あなたへのおすすめ」セクション**: 共通参加者の多いグループを協調フィルタで提案
- **多言語対応**: 海外コミュニティの増加に備え、英語タグも検索対象に
- **無限スクロールとページネーションの併用**: SEO 観点ではページネーションを残しつつ UX で infinite を選べるとよい
- **公開状態の一貫性**: connpass は「グループ非公開」を許可しないが、模倣する場合は「招待制」モードを別途検討する余地あり

## 補足: connpass の「グループ」概念整理

### グループとイベントの関係

- イベントは「個人主催」か「グループ主催」のいずれか
- グループに紐付けたイベントは、そのグループのフォロワーに告知メールが送られる
- グループ TOP に過去・未来イベントが時系列で並ぶ
- 一度グループ紐付けしたイベントは、別グループへの付け替え不可

### グループの公開原則

- connpass のグループはすべて公開（非公開・招待制のオプションは存在しない）
- メンバー一覧やイベント履歴を非公開にする設定は提供されていない
- 例外: 「メンバー限定イベント」設定により、特定イベントだけ参加資格を「グループメンバーのみ」に絞れる

### グループ一覧での「公開グループだけ表示する」フィルタ

- そもそも非公開グループが存在しないため、フィルタとしては不要
- ただし、長期間休眠（最終イベントから 1 年経過など）したグループを除外するフィルタは UX 上有効

## 一覧画面で起こりうるソート / フィルタの組合せパターン

| シナリオ | 推奨ソート | 推奨フィルタ |
| -------- | --------- | ----------- |
| 新規ユーザーが入会先を探す | メンバー数順 | 興味タグ |
| 採用担当者が PR 先を探す | 開催頻度順 | 地域 + タグ |
| 主催候補がジャンルを下見 | 直近イベント順 | カテゴリ |
| ジャーナリスト的探索 | 急成長順 | 集計期間 |
| 既存ユーザーの再発見 | フォロー中ユーザーが参加中 | 興味タグ |

## アーキテクチャ上のメモ

- グループ一覧はキャッシュフレンドリーな静的データ（タイトル、メンバー数、サムネ）が多く、CDN 配信に向く
- 並び順だけ動的（DB 集計）にして、上位ページのみ ESI / Edge Side Includes で差し込み
- 検索は Elasticsearch / OpenSearch / Meilisearch などで全文インデックス
- ロケール / 言語別のサブインデックスを用意し、英語タグも含めた検索を可能に
- グループのサムネとカバー画像は画像 CDN（CloudFront / Imgix）で動的リサイズ

## 国際化と将来の拡張

- 海外イベント（PyCon US, KubeCon 等）の連携や、英語コミュニティの取り込みを意識する場合、タグや説明の多言語化が必要
- 国別フィルタ、タイムゾーン別の「直近開催」フィルタも候補
- パスベースの URL (`/groups/`) なら、`/en/groups/` のような多言語ルーティングが取りやすい

## 計測すべき指標

- グループ詳細ページの一覧経由のクリック率（CTR）
- 「メンバーになる」CTA の一覧→詳細→参加転換率
- タグ別の検索クエリ数
- ページ深度（何ページ目までスクロール / ページネーションされるか）
- カテゴリ別の新規グループ作成数
- 空ヒット率（検索しても結果が出ないクエリ）

## ペルソナ別の利用シナリオ

### ペルソナ A: 新卒エンジニア（学習目的）

- 「Python」「Web 開発」「初心者」タグで検索
- メンバー数の多いグループから順に閲覧
- 「もくもく会」「LT 会」を優先

### ペルソナ B: 中堅エンジニア（情報収集）

- 興味のある技術キーワードで検索
- 直近イベントが近いグループにフォーカス
- 主催者やコアメンバーの所属企業をチェック

### ペルソナ C: 採用担当（露出目的）

- 自社の技術スタックに合うグループを発見
- 規模 + 開催頻度で評価
- 主催者にコンタクトする手がかりを得る

### ペルソナ D: 主催者（ベンチマーク）

- 競合 / 類似グループの活動を観察
- 自グループの強みを再確認

## 一覧ページ作成時のチェックリスト

- [ ] SSR + CSR ハイブリッドで初回表示が速い
- [ ] 構造化データ (ItemList) でクローラ最適化
- [ ] 並び順切替の URL がブックマーク可能
- [ ] 検索クエリのデバウンス処理
- [ ] 結果 0 件時のフォールバック UI
- [ ] 無限スクロール（任意）とページネーション併存
- [ ] アクセシビリティ（フォーカス管理、ARIA）
- [ ] 画像の lazy loading
- [ ] ダークモード対応
