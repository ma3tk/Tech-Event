# ログイン・新規登録ページ

## 概要・目的

connpass のログイン / 新規登録ページは、すべての書き込み系・パーソナライズ機能（イベント申込、グループ参加、主催、設定など）の入り口となる、サービス利用の起点ページである。

主な目的:

- 既存ユーザーの認証（ユーザー名 / メールアドレス + パスワード、または外部 IdP）
- 新規ユーザーのアカウント作成
- 外部 IdP（X / Facebook / GitHub）との連携によるパスワードレス導線
- パスワードリマインダーの提供
- メール認証フローの起点
- 利用規約・プライバシーポリシー同意の取得

connpass は IT 勉強会プラットフォームという性質上、X (Twitter) / GitHub アカウントを持つユーザーがほとんどであるため、外部連携ログインが特に重要。

## URL 構造

- ログイン: `https://connpass.com/login/`
- 新規登録: `https://connpass.com/signup/`
- パスワードリセット要求: `https://connpass.com/account/password_reset/`
- パスワードリセット完了: `https://connpass.com/account/password_reset/done/`
- パスワード再設定（メールリンク）: `https://connpass.com/account/reset/{token}/`
- メール認証: `https://connpass.com/account/email_confirm/{token}/`
- ログアウト: `https://connpass.com/logout/`
- 外部 IdP コールバック:
  - `https://connpass.com/account/twitter/callback/`
  - `https://connpass.com/account/facebook/callback/`
  - `https://connpass.com/account/github/callback/`
- ログイン後リダイレクト: `?next=/event/{event_id}/` のようなクエリで遷移先指定

## フォーム項目（詳細）

### ログイン入力

- **識別子**: ユーザー名でもメールアドレスでもログイン可。サーバ側で `@` 含有かで判定
- **パスワード**: 表示 / 非表示切替の目アイコン
- **ログイン状態保持**: チェック時はセッション Cookie の expires が延長 (例: 30 日)

### 新規登録入力

- **ユーザー名**:
  - 入力中にリアルタイムで「使用可能か」チェック（XHR）
  - 重複時は「このユーザー名は既に使用されています」
  - 予約語（admin, support, help 等）は拒否
- **メールアドレス**:
  - 仮登録 → 確認メール送信 → リンククリックで本登録の 2 段階
- **パスワード**:
  - 強度メーター（弱 / 中 / 強）
  - 「半角英数字で 6 文字以上」と明示
- **同意チェック**:
  - リンク先: `https://connpass.com/term/` / `https://connpass.com/privacy/`

### 外部ログイン連携

- **X (Twitter)** OAuth 2.0
- **Facebook** OAuth 2.0 / Graph API
- **GitHub** OAuth 2.0
- 外部 IdP で初回登録時はメールアドレスとユーザー名の追加入力ステップに遷移（メールが取れない場合）

## 配置されている UI コンポーネント

- 入力フィールド + バリデーションエラー表示
- パスワード表示 / 非表示トグル
- パスワード強度メーター
- 外部ログインボタン（各サービスのブランドカラー）
- 区切り線「── または ──」
- 利用規約同意チェックボックス
- 「ログインする」「登録する」プライマリボタン

- トラブルシューティング案内（クッキー削除）
- インフォメーション / 警告バナー（メンテナンス時など）

## 状態による出し分け

- **未入力 / バリデーションエラー**: 各フィールド直下に赤字
- **CSRF トークン不正**: フォーム再表示 + 警告
- **アカウントロック (5 回失敗等)**: 「しばらく経ってから再度お試しください」
- **メール未認証**: ログイン後に「メール認証してください」ページに飛ばす
- **既ログイン状態でアクセス**: トップ or マイページへリダイレクト
- **next クエリあり**: ログイン後に元の URL へ戻す
- **モバイル**: 外部ログインボタンが先頭に来ることもある

## インタラクション

- フォーム送信時の loading 表示
- 外部ログインクリック → IdP の認可画面 → コールバック → connpass へ戻る
- ユーザー名フィールド blur で重複チェック XHR
- パスワード入力中に強度メーター更新
- パスワードリセットメール送信後の確認ページ表示
- 「クッキーを削除して再ログイン」案内（ヘルプ通り）
- ログイン成功時、`Set-Cookie` + redirect

## 推測される API コール

- `POST /account/login/` — フォーム送信 (Django 流の form ベース)
- `POST /account/signup/` — 新規登録
- `POST /account/password_reset/` — リセットメール送信
- `POST /account/reset/{token}/confirm/` — 新パスワード設定
- `GET /account/email_confirm/{token}/` — メール認証
- `GET /account/twitter/authorize/` → IdP へ
- `GET /api/v1/account/check_username/?username=...` — リアルタイム重複チェック
- `POST /account/logout/`
- 内部に reCAPTCHA / hCaptcha 検証

## 関連リンク・遷移先

- 利用規約 (`/term/`)
- プライバシーポリシー (`/privacy/`)
- 特定商取引法表記
- ヘルプ「会員登録をする」「ログインする」
- 新規登録 → メール認証 → 興味タグ入力 → マイページ
- パスワードリセット完了 → ログイン

## 模倣実装する際の留意点

- **ユーザー名の予約**: `admin`, `support`, `event`, `group`, `api`, `help` 等は予約
- **メール認証必須化**: 未認証アカウントは投稿不可 / 申込制限など
- **OAuth スコープ最小化**: 外部 IdP で取得するのはプロフィールとメールのみ
- **複数 IdP の集約**: 同一メールアドレスで複数 IdP を後から紐付け可能に
- **2 要素認証**: テックユーザーは多要素認証を求めることが多い。TOTP / WebAuthn 対応推奨
- **レート制限**: ログイン失敗、リセット要求、登録に対してアカウント単位 / IP 単位の rate limit
- **CSRF**: フォームすべてにトークン付与、SameSite Cookie
- **パスワードハッシュ**: bcrypt / argon2 推奨。connpass はおそらく Django 標準の PBKDF2
- **メール認証トークン**: 有効期限あり (24 時間程度)、ワンタイム
- **next パラメータの検証**: オープンリダイレクト防止のため同一ホストのみ許可
- **パスワード強度**: 6 文字は弱い。模倣実装では 8 文字 + 推奨ルールを
- **退会済ユーザー名の再利用**: 衝突回避のため一定期間は再利用不可
- **OGP / メタ**: ログイン / 登録ページは noindex 推奨
- **アクセシビリティ**: `aria-required`, `aria-invalid`, ラベル明示、スクリーンリーダー
- **外部ログインボタンのブランドガイドライン**: 各 IdP のロゴ・色は規約遵守
- **MFA バックアップコード**: 多要素認証導入時はリカバリーコードの発行
- **ボット対策**: hCaptcha / reCAPTCHA v3 をサインアップフォームに必須化
- **メールアドレス変更フロー**: 新メール認証完了後に旧メール失効
- **ログインメールへのリンク認証 (Magic Link)**: パスワードレス UX として効果的
- **iOS / Android 自動入力**: `autocomplete` 属性（`username`, `current-password`, `new-password`）を適切に
