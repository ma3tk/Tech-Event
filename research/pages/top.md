調査日: 2026-06-04
対象URL: https://connpass.com/
備考: 本ドキュメントは公開HTMLおよびWebFetchで取得した構造観察に基づく一次調査メモであり、模倣実装は「機能のクローン」に留め、文言・画像・スタイル等の著作物は直接複製しない方針で記述する。

## 1. 概要・目的

connpass のトップ (ルート `/`) は「エンジニア向けIT勉強会支援プラットフォーム」のランディング兼ハブとして機能している。主な役割は次の3つに整理できる。

1. **サービスの価値訴求**: 初訪問ユーザーに対して "勉強会・コミュニティ運営を支援するSaaS" であることを端的に伝える。
2. **ディスカバリー導線**: 新着イベント、注目グループ、ランキング、カレンダーなどへの導線を1ページに集約し、回遊性を高める。
3. **アカウント獲得**: 「ログイン・新規登録」と「イベントを作成する」を主要CTAとして、主催者・参加者双方の登録を促す。

トップに直接 SEO 流入してくるユーザー (検索クエリ「connpass」「IT勉強会」など) と、リピーターのうちブックマーク経由でアクセスしてくるユーザーの両方を想定したデュアル目的のページである。

## 2. URL構造とパスパターン

| パターン | 説明 |
| --- | --- |
| `https://connpass.com/` | トップページ本体。クエリパラメータは通常不要。 |
| `https://connpass.com/?utm_source=...` | 外部広告/SNS流入時に `utm_*` パラメータが付くことがある (一般的な計測想定)。 |
| `https://connpass.com/?lang=ja` 等 | 多言語切替の余地はあるが、現在 `ja` がデフォルト挙動。 |

主要な発着リンク先 (トップから遷移可能なURL群):

- `/explore/` — 新着イベント一覧
- `/explore/?page=2..N` — ページネーション
- `/ranking/` — イベントランキング
- `/calendar/` — カレンダービュー
- `/about/` — サービス紹介
- `/feed/` — Atomフィード
- `/series/{slug}/` — カンファレンス特集
- `{group_slug}.connpass.com` — グループ専用サブドメイン
- `/event/{event_id}/` — イベント詳細 (グループサブドメインへ302リダイレクトする実装)
- `/login/`, `/signup/` (推測) — 認証フロー

ロケール/SEO 観点では canonical URL は `https://connpass.com/` で、末尾スラッシュあり形式。`utm_*` などの計測パラメータは canonical で正規化される設計が望ましい。

## 5. 配置されているUIコンポーネント

- **AppHeader** : ロゴ, ナビリンク, 検索トリガ, CTAボタンを並列配置するスティッキー想定ヘッダー。
- **PrimaryButton / SecondaryButton** : HERO の2種CTA。primary は塗り潰し、secondary はアウトラインが定石。
- **FeatureCard** : アイコン or イラスト + タイトル + 説明文の縦積み。等高揃え推奨。
- **GroupChipCard** : アバター + グループ名 + 統計 (回数/メンバー数)。横並び。
- **EventCard** : サムネ + 日付バッジ + タイトル + 主催者 + 参加状況。新着リスト・検索結果で再利用。
- **FooterColumns** : 4列のリンクグループ + 著作権表記。
- **OverlaySearchBar** (推測) : 検索アイコン押下で展開するモーダル/ドロップダウン。

State として持つべきもの:

- `isAuthenticated` : ヘッダーCTAの切替 (ログイン状態なら「マイページ」「通知」など)。
- `featuredGroups` : サーバから返ってくるレコメンド配列。
- `recentEvents` : 新着配列。

## 6. 状態 (Auth/Role) による出し分け

| 状態 | ヘッダー右側 | HERO | 新着イベントカード | 主催CTA |
| --- | --- | --- | --- | --- |

## 7. インタラクション

- **HERO CTA hover**: 微細な色変化 + シャドウ強調 (推測)。
- **イベントカード hover**: 画像のズーム or シャドウ拡大 + タイトル下線。
- **グループカード hover**: アバター拡大、加入ボタンが出現する余地。
- **検索アイコンクリック**: オーバーレイ検索 UI が下方/モーダルで展開。Esc で閉じる。
- **"もっと見る" クリック**: `/explore/` へページ遷移 (full page navigation)。
- **スクロール**: ヘッダーは固定 (推測)。フッターまで連続スクロール、無限スクロールは行われない。
- **キーボード操作**: タブ順は ヘッダー → HERO CTA → 機能カード → グループ → 新着 → フッター の論理順序が望ましい。
- **画像の遅延ロード**: 新着イベントカードのサムネは `loading="lazy"` を想定。

## 8. 推測されるAPIコール

トップは初回HTMLにある程度 SSR で埋め込まれていると見られるが、機能要件としては以下のエンドポイントが必要になる。

| 種別 | エンドポイント (想定) | パラメータ | レスポンス | 備考 |
| --- | --- | --- | --- | --- |
| 新着イベント | `GET /api/v1/events?order=created_desc&limit=8` | `limit`, `order` | `{ events: [...] }` | 公開APIは `count`/`order`/`series_id` 等。 |
| 注目グループ | `GET /api/v1/groups?featured=true&limit=6` | `featured`, `limit` | グループ配列 | 編集者が手動で featured を付与する想定 |
| ランキング先頭 | `GET /api/v1/events/ranking?limit=N` | `period` (month/week) | 順位付きイベント配列 | トップで上位3件など表示する場合 |
| 認証状態 | `GET /api/v1/me` | (cookie) | `{ user_id, name, avatar }` | ヘッダー出し分け |
| 検索オーバーレイ | `GET /api/v1/events?keyword=...&limit=10` | `keyword`, `tag`, `start_date`, `end_date` | 検索結果配列 | 検索バー入力時 |

connpass 公式の v1/v2 API (`/api/v1/event/`) を踏襲するならば、フィールド名は `event_id`, `title`, `started_at`, `ended_at`, `address`, `place`, `lat`, `lon`, `owner_nickname`, `accepted`, `waiting`, `limit` などになる。

## 11. レスポンシブ対応

- 想定ブレークポイント: モバイル (〜640px), タブレット (〜960px), デスクトップ (961px〜)。
- モバイル時:
  - グローバルナビはハンバーガーメニュー化、検索アイコンはヘッダー残存。
  - HERO のキャッチコピーは2行折返し、ボタンは縦並び。
  - 機能カード6個は1列 (縦スクロール) または2列に折返し。
  - グループ・新着は横スクロール (`overflow-x: auto`) のカルーセル化が自然。
- タッチターゲットは44px以上を確保 (Apple HIG 準拠)。
- フッターは4カラム → 2カラム → 1カラム アコーディオン化 が定石。

## 12. アクセシビリティ観点で気づいたこと

- ロゴ画像には `alt="connpass"` 相当が必要。
- HERO の h1 は1つだけにし、機能カードのタイトルは h2/h3。
- "ログイン・新規登録" は1つのボタンに2機能をまとめており、スクリーンリーダー利用者にはモーダル内で明確にラベル分けする必要がある。
- 日付バッジ "6月 27" は視覚情報のため、`<time datetime="2026-06-27">` で機械可読化が望ましい。
- 参加者数 "0/45人" は分数表現で読まれる恐れがあるので `aria-label="申込0人、定員45人"` 等で補強。
- カードリンクが画像とタイトルの両方にあると `tabindex` 重複が発生し得る → ラップ要素1つに統合し、`aria-labelledby` でタイトルを参照。
- カラーコントラスト: 日付バッジ、ステータスバッジは AA (4.5:1) 以上を満たす配色にする。
- キーボードフォーカスの可視リング維持。
- ハンバーガーメニューは `aria-expanded`, `aria-controls` を付与。

## 13. 模倣実装する際の留意点

1. **著作物の非複製**: ロゴ、機能カードのイラスト、キャッチコピーはそのまま流用しない。自前のブランド資産で代替する。
2. **情報設計のみクローン**: 「HERO → 機能訴求 → 注目グループ → 新着イベント → フッター」の縦積み構造は汎用設計として再利用可。
3. **CTAの優先順位**: 主CTA (新規登録) と副CTA (イベント作成) のヒエラルキーを崩さないことが本質。トーンや色の差別化を確実に。
4. **新着イベントAPI**: 自前で運用するなら limit=8 程度のキャッシュ付きエンドポイントを用意し、CDNで分単位キャッシュすると良い。
5. **SSR + ISR推奨**: トップは更新頻度が高くないため、Next.js なら ISR (revalidate=60秒程度) や `getStaticProps + revalidate` が適切。
6. **SEO**: ホームページはルートドメインの最重要ページ。`title`/`description`/`og`/`twitter`/`canonical`/構造化データを必ず揃える。
7. **国際化の余地**: 当面日本語のみで良いが、URLは `/ja/`, `/en/` 等の prefix を視野に入れた設計にしておく。
8. **計測**: GA4 や自前計測で「HERO CTAクリック」「新着カードクリック (順位付き)」「もっと見るクリック」を分離して取れるよう、`data-*` 属性を付与しておく。
9. **空状態のハンドリング**: 新着イベント0件、注目グループ0件のケースで崩れないよう、スケルトン or 訴求パネルを準備。
10. **パフォーマンス**: 画像は `next/image` 等で最適化し、Above the fold の3枚を `priority`、それ以下を `lazy`。
11. **A11y チェック**: axe-core / Lighthouse の Accessibility 90点以上を目標に。
12. **法務リンクの初期整備**: 利用規約・プライバシーポリシー・特商法表示は MVP 段階から空でも良いから設置必須。

## 14. リスク・未確認事項

- トップに広告枠 (運営会社向け広告) が差し込まれる時間帯がある可能性 (今回の観測では未検出)。
- ログイン状態でのトップ表示 (推薦ロジック) は未認証では検証不可。マイページへ自動リダイレクトされる可能性も検討。
- A/B テストによるバリアントの可能性。HERO 文言は時期によって異なるかもしれない。
