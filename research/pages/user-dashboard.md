# マイページ (ユーザーダッシュボード)

## 概要・目的

connpass にログインした直後に表示される「マイページ」は、ユーザーが connpass 上で行うすべての行動（イベント探し、参加管理、グループ管理、設定）の起点となるダッシュボード。ログイン状態でしか到達できないため公開情報からは正確な構造は把握できないが、connpass のヘルプ記事と他ユーザーの公開プロフィールから、以下のような構成が推測できる。

主な目的:

- 自分の予定（今後の参加イベント）の即時把握
- 興味あるイベント・グループへの素早いアクセス（ブックマーク、フォロー）
- 自分が管理しているグループ・イベントへの管理導線
- アカウント設定、メール通知設定、API キー管理など運用導線
- 「あなたへのおすすめ」推奨イベントの提示

## URL 構造

- マイページ TOP（推測）: `https://connpass.com/dashboard/` or `https://connpass.com/`（ログイン時はパーソナライズ）
- 参加予定イベント: `https://connpass.com/dashboard/event/upcoming/`
- 申込履歴: `https://connpass.com/dashboard/event/history/`
- ブックマーク: `https://connpass.com/dashboard/bookmark/`
- 所属グループ: `https://connpass.com/dashboard/group/`
- 管理中グループ / イベント: `https://connpass.com/dashboard/manage/`
- 設定:
  - プロフィール編集: `https://connpass.com/account/profile/`
  - パスワード変更: `https://connpass.com/account/password/`
  - メール通知設定: `https://connpass.com/account/mail/`
  - 外部連携: `https://connpass.com/account/connection/`
  - API キー: `https://connpass.com/account/api/`
  - 退会: `https://connpass.com/account/withdraw/`

ヘルプ記事「気になるイベントをブックマークする」では「ホーム画面内の専用タブ、およびプロフィールページで確認可能」と明記されている。これより、ホーム画面（マイページ）内にはタブナビゲーションが存在することが分かる。

## 各タブの内訳

### 参加予定 (Upcoming)

- 今後開催される、申込済みイベント
- 各カード: 日時 / タイトル / グループ / 申込ステータス (確定 / 補欠 / 抽選待ち)
- 「キャンセル」「受付票表示」「カレンダーに追加」アクション

### 申込履歴 (History)

- 過去・現在のすべての申込
- フィルタ: 開催前 / 終了 / キャンセル / 抽選漏れ
- 領収データ発行リンク（有料時）

### ブックマーク (Bookmark)

- 自分がブックマークしたイベント
- 開催前 / 終了で表示切替
- 「申込に進む」CTA

### 管理 (Manage)

- 自分が管理者のイベント / グループ一覧
- 「新しいイベントを作成」「新しいグループを作成」CTA
- 管理イベントには参加者数 / 定員、申込状況、ステータス

### グループ (Groups)

- 所属しているすべてのグループ
- 通知設定（毎回 / ダイジェスト / オフ）
- 「退会」リンク

### おすすめ (Recommend)

- ヘルプ記事より:
  - 「あなたがフォローしているユーザーのブックマークしたイベントも表示されます」
  - つまり、興味タグ + 所属グループ + フォローユーザーの活動を組み合わせたレコメンド

## 設定ページの項目（推測詳細）

### プロフィール編集

- 表示名（変更可）
- 自己紹介（Markdown）
- アバター画像
- ロケーション
- Web URL
- X / Facebook / GitHub 名
- 興味タグ
- 公開範囲（活動履歴の公開可否）

### メール通知設定

- グループ別の通知頻度
- 受付確認メールの送信有無
- 抽選結果メール
- リマインダーメール（前日 / 当日）
- マーケティングメール
- 主催者からの一斉送信メール

### 外部連携

- X / Facebook / GitHub の連携 / 解除
- カレンダーサービス連携 (Google Calendar / iCloud)
- iCal フィードの URL

### API 設定

- API キー発行（読み取り専用）
- レート制限の残量表示
- 利用履歴

### 決済 / 受領設定（有料イベント主催者）

- PayPal メールアドレス
- 領収書情報（事業者名、適格請求書登録番号、所在地）

### 退会

- 退会理由アンケート
- 退会確認

## 状態による出し分け

- **初回ログイン**: チュートリアル / 興味タグ入力ウィザード
- **参加予定 0 件**: 「イベントを探す」CTA
- **管理イベント 0 件**: 「イベントを作成する」CTA
- **未確認通知あり**: 通知バッジが赤
- **当日イベント**: トップに「本日のイベント」セクションを強調
- **有料イベントの未決済あり**: 警告バナー
- **抽選待ち**: 「抽選は M 月 D 日に実施されます」表示
- **メール未認証**: 「メールアドレスを確認してください」バナー

## インタラクション

- タブ切替で URL ハッシュ更新（SPA 風）
- イベントカード単独クリックで詳細
- カレンダー連携リンクで Google Calendar / iCal をワンクリック追加
- 出席コード入力で当日チェックイン
- キャンセルアクション → 確認モーダル → 補欠繰り上げ通知
- 通知ベルクリックでドロップダウン表示、既読化
- 「もっと見る」で次ページ
- 「すべて既読にする」

## 推測される API コール

- `GET /api/v1/me/` — 自分のプロフィール
- `GET /api/v1/me/event/?status=upcoming` — 参加予定
- `GET /api/v1/me/event/?status=history` — 履歴
- `GET /api/v1/me/bookmark/` — ブックマーク
- `GET /api/v1/me/group/` — 所属グループ
- `GET /api/v1/me/managed/` — 管理イベント / グループ
- `GET /api/v1/me/notification/` — 通知
- `GET /api/v1/me/recommend/` — レコメンド
- `PATCH /api/v1/me/profile/` — プロフィール更新
- `PATCH /api/v1/me/mail_setting/` — 通知設定
- `POST /api/v1/event/{event_id}/attend/` — 出席登録
- `DELETE /api/v1/event/{event_id}/join/` — キャンセル
- `POST /api/v1/account/api_key/` — API キー発行

## 模倣実装する際の留意点

- **パーソナライズの初期化**: 新規ユーザーは興味タグや所属がないのでおすすめが空になる。オンボーディングで興味タグ入力を必須化する手も
- **タイムゾーン**: ユーザー設定のタイムゾーンで日時を表示
- **通知の頻度設計**: connpass 同様、「即時 / ダイジェスト / オフ」の 3 段階を基本に、グループごと・カテゴリごとに細かく設定可能
- **当日イベントの強調**: 「今日のイベント」を最上部に固定し、Zoom URL や出席コードを即座に表示
- **レコメンドアルゴリズム**:
  - 興味タグ x イベントタグの一致
  - フォロー中ユーザーのブックマーク・参加
  - 所属グループの新着
  - 過去参加実績との類似（embedding）
- **抽選通知**: 抽選日が決まっているため、UI 上でも「抽選日 N 日後」を明示
- **キャンセルの摩擦**: キャンセル時に「補欠が繰り上がります」と表示し、心理的ハードルを下げる
- **複数管理者の権限**: 「自分が管理者」と「自分は発表者だけど告知に名前が出る」の違いを区別
- **アクセシビリティ**: 通知ベル、タブ、ドロップダウンに ARIA を付与
- **API キーのセキュリティ**: 生成時のみ全文表示、以降は末尾 4 桁のみ表示
- **退会フロー**: 退会後の参加履歴・主催イベントの扱いをユーザーが選択（公開継続 / 匿名化 / 削除）
- **データエクスポート**: GDPR 対応の活動履歴 CSV ダウンロード
- **モバイル UX**: タブをスクロール可能に、ヘッダー固定、フローティング検索ボタン
- **オフライン対応**: 参加予定の主要情報をローカルキャッシュし、会場入場時の電波弱い環境でも確認可能に
- **多言語対応**: 海外イベントが増えているため、英語 UI を準備
- **マーケティングメール最適化**: 一斉送信メールを送りすぎるとオフ率が上がる。グループ単位 + ユーザー設定で適切に
