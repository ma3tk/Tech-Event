# ユーザープロフィールページ

## 概要・目的

connpass のユーザープロフィールページは、特定ユーザーの活動履歴・所属コミュニティ・興味分野・ネットワークを集約表示する公開ページである。connpass はイベントとグループを中心としたサービスだが、ユーザーは「参加者」「主催者」「発表者」の三役を兼ねるため、プロフィールページはそれらの活動を一元的に証明する「実績ポートフォリオ」としての性格を持つ。

主な目的:

- 自分の活動履歴を整理・PR
- 他者の信頼性確認（採用文脈、登壇打診、共催相談）
- フォロー / フォロワーによる緩いネットワーク
- 興味の近いイベントを発見する起点
- 発表資料のショーケース

参考に閲覧した実例:

- `https://connpass.com/user/haru860/` — 利用開始 2011/10/20、参加 439 / 管理 387 / 発表 64 / ブックマーク 85
- `https://connpass.com/user/shimizukawa/` — 利用開始 2011/10/20、参加 847 / 管理 655 / 発表 38 / ブックマーク 135、所属 11 グループ、フォロー 4、フォロワー 32

## URL 構造

- プロフィール TOP: `https://connpass.com/user/{username}/`
- 開催イベント: `https://connpass.com/user/{username}/open_events/`
- 参加イベント: `https://connpass.com/user/{username}/joined_events/`
- 管理イベント: `https://connpass.com/user/{username}/managed/`
- 発表履歴: `https://connpass.com/user/{username}/presented/`
- ブックマーク: `https://connpass.com/user/{username}/bookmarks/`
- フォロー: `https://connpass.com/user/{username}/following/`
- フォロワー: `https://connpass.com/user/{username}/followers/`
- 所属グループ: `https://connpass.com/user/{username}/groups/`

`{username}` は新規登録時に決めるサイト内 ID（半角英数 + `- _`、30 文字以内、登録後変更不可）。

```

│ Global Header                                              │
├────────────────────────────────────────────────────────────┤
│ ┌─ Avatar ─┐  ユーザー名 (表示名)                          │
│ │          │  @username                                   │
│ │          │  利用開始日: 2011/10/20                       │
│ └──────────┘  自己紹介 (Markdown / プレーンテキスト)         │
│   [X] [FB] [GitHub] [Web]                                 │
│   [フォローする]  [メッセージ]                              │
├────────────────────────────────────────────────────────────┤
│ 活動統計バー: 参加 847 / 管理 655 / 発表 38 / ブックマーク 135 │
├────────────────────────────────────────────────────────────┤
│ タブ: [概要] [参加] [管理] [発表] [ブックマーク] [グループ]  │
├──────────────┬─────────────────────────────────────────────┤
│ サイドバー    │ メイン (タブに応じて切替)                    │
│ ・所属グループ │ 例: 参加履歴の時系列カード一覧               │
│ ・フォロー    │                                              │
```

レスポンシブではサイドバーが下に折り返り、タブはスクロール可能な水平リストになる。

### 各タブで表示されるレコード

#### 参加イベント

- 日付
- ステータス (参加 / キャンセル / 補欠 / 抽選漏れ / 出席済 / 欠席)
- イベントタイトル
- 所属グループ
- 申込枠

#### 管理イベント

- 開催ステータス
- イベントタイトル
- 参加者数 / 定員
- 開催日

#### 発表 (Presentation)

- スライドサムネ
- タイトル
- 発表日
- 紐づくイベント

#### ブックマーク

- イベント一覧 (申込はしていないがブックマークしたもの)

## 配置されている UI コンポーネント

- アバター + 名前カード
- ソーシャル連携アイコン群（X / Facebook / GitHub / Web）
- 統計バッジ（参加 / 管理 / 発表 / ブックマーク）
- タブナビゲーション
- イベントカードリスト
- グループアバターグリッド
- フォロー / フォロワー横スクロールリスト
- フォローボタン (ログイン時, 他者プロフィール)
- 編集ボタン (自分のプロフィール時)
- 公開設定アイコン（一部項目を非公開にしている場合）

## 状態による出し分け

- **未ログイン閲覧**:
  - フォローボタンが「ログインしてフォロー」になる
  - 一部の活動（ブックマーク）が非表示の可能性
- **本人閲覧**:
  - 「プロフィール編集」ボタン
  - 公開・非公開設定が表示
- **フォロワー / フレンド**:
  - フォロワー限定の活動が表示される可能性
- **フォロー済 / 未フォロー**: ボタンラベル切替
- **企業アカウント**: 採用情報ブロックが追加表示される可能性
- **退会済ユーザー**: 「このユーザーは退会しました」と表示

## インタラクション

- タブ切替で URL ハッシュ or path 遷移
- フォローボタン → 即時 toggle、トースト通知
- イベントカードクリックでイベント詳細へ
- グループアイコンクリックでグループ詳細へ
- フォロー / フォロワー一覧で「もっと見る」ページング
- 発表資料サムネクリックで外部スライド（Speaker Deck 等）にジャンプ
- プロフィール編集（本人時のみ）→ 設定画面へ
- 通報 / ブロック（他者プロフィール時）

## 推測される API コール

- `GET /api/v1/user/{username}/` — プロフィール基本
- `GET /api/v1/user/{username}/event/?status=joined&page=1` — 参加履歴
- `GET /api/v1/user/{username}/event/?status=managed` — 管理イベント
- `GET /api/v1/user/{username}/presentation/` — 発表履歴
- `GET /api/v1/user/{username}/bookmark/` — ブックマーク
- `GET /api/v1/user/{username}/group/` — 所属グループ
- `GET /api/v1/user/{username}/following/` — フォロー一覧
- `GET /api/v1/user/{username}/follower/` — フォロワー一覧
- `POST /api/v1/user/{username}/follow/` / `DELETE` — フォロー操作

公開 API では event 検索の `nickname` フィルタを使うとユーザー単位の参加イベントを取得可能。

- 各参加 / 管理 / 発表したイベント詳細
- 所属グループ詳細
- フォロー / フォロワー個別プロフィール
- 発表資料の外部リンク
- 「プロフィールを編集」（本人時）
- 「メール通知設定」（本人時）

## 模倣実装する際の留意点

- **本名 / HN の取扱**: connpass は本名表示が多い。模倣する場合は「本名公開」「HN のみ」を切替可能に
- **公開範囲制御**: 参加イベントを非公開にしたいユーザーが一定数いる。プライバシー設定は重要
- **ID 不変性**: ユーザー名は URL に使う以上、安易な変更を許すと参照リンクが壊れる。リダイレクト戦略が必要
- **活動統計のキャッシュ**: 数百〜数千の参加履歴を集計する場合、リアルタイムではなくバッチ集計
- **SNS 連携 OAuth**: GitHub / X / Facebook と OAuth 連携した場合、リンク自動補完 + 認証強化に活用
- **発表資料の埋め込み**: Speaker Deck oEmbed や Google Slides iframe での表示を実装
- **フォロー機能の通知**: フォローしたユーザーのブックマーク・参加イベントを「おすすめ」に活用
- **採用利用への配慮**: connpass はエンジニア採用文脈で見られるため、HR タグ / Find Job 連携を意識
- **スパム / なりすまし対策**: 同一名・同一アバターでの大量アカウント作成防止
- **退会時の挙動**: プロフィールページを 410 or 「退会済」表示にし、過去発表だけ残す等の選択肢
- **GDPR / 個人情報保護**: 活動履歴をエクスポート、削除依頼に応じる仕組み
- **OG タグ**: プロフィール毎に OGP を生成し、X / Slack でのシェア時に発表者として見栄えする
- **アクセシビリティ**: 数値統計に aria-label を付与し、スクリーンリーダーで「参加 847 件」と読まれるように
- **SEO**: 発表履歴ページは外部リンクが多い。`rel="ugc"` などの適切な属性付与
- **テーマ表示**: ユーザーが自分の色（ブランドカラー）を選べる UI も検討余地
- **公開 / 非公開フラグの粒度**: 全体公開 / フォロワーのみ / 非公開 をフィールドごと（プロフィール本文・参加履歴・ブックマーク）に設定可能とすることが望ましい

## サブページ別 詳細

### 参加イベント一覧 (`/joined_events/`)

- すべての参加履歴を時系列で表示
- フィルタ: 開催前 / 終了 / キャンセル / 抽選漏れ
- 年別ヘッダー（2024 年、2023 年…）
- 大量のイベントを参加するユーザー（例: shimizukawa の 847 件）に対応するため Cursor ベースのページング

### 管理イベント一覧 (`/managed/`)

- 主催または管理者として登録されたイベント
- ステータス別タブ: 開催前 / 開催中 / 終了
- 参加者数 / 定員 / 申込率
- 主催側で見るマイページの「管理」と同様 UI を再利用

### 発表履歴 (`/presented/`)

- 発表したイベント + 資料のサムネ
- 外部スライドのプレビュー（Speaker Deck の oEmbed など）
- 発表日時 / 紐づくイベント
- 「ポートフォリオ」として活用される

### ブックマーク (`/bookmarks/`)

- 公開設定の場合のみ他者から閲覧可能
- 自分が「参加していないが気になっている」イベント
- フォロー中ユーザーのブックマークを参考に発見性が広がる

### 所属グループ (`/groups/`)

- グリッド表示 + メンバー数 + 開催イベント数
- グループアイコンクリックで詳細へ

### フォロー / フォロワー

- フォローしているユーザー / フォロワーのアバター一覧
- 名前・自己紹介抜粋
- 共通の参加イベント数（推測）
- フォローバック導線

## ユーザーの「実績」表現の意義

- 参加 847 件のような数値は、コミュニティへの長期的コミットメントを可視化
- 「Sphinx コミッター」など肩書きとセットで PR ポートフォリオとして機能
- 「管理 655 件」は主催実績として登壇打診や採用文脈で参照される
- 「発表 38 件」は発表者としての権威性を示す

## ソーシャル機能の活用ユースケース

- 共催相手の信頼性チェック
- 登壇者打診時の発表履歴確認
- 採用候補者の活動把握（候補者がパブリックに同意している場合）
- ジャーナリスト・学生による研究対象探し
- コミュニティ内のメンター発見

## 公開範囲制御の重要シナリオ

- 副業バレ防止: 参加 / 管理イベントを非公開
- 学生プライバシー保護
- 退職後の所属企業グループの表示制御
- 一時的な非公開（転職活動中など）

## 推測される編集 UI

プロフィール編集 (`/account/profile/`) の項目:

- 表示名（変更可、ユーザー名と別）
- アバター（画像アップロード、X / GitHub から自動取得オプション）
- 自己紹介（Markdown 対応）
- ロケーション
- 所属企業 / 肩書き
- 興味タグ（マルチセレクト + 自由入力）
- Web サイト URL
- 各 SNS のユーザー名
- 公開範囲設定（プロフィール本文 / 参加履歴 / ブックマーク 各々）
- メール公開有無（基本は主催者のみ参照可）

## OG タグの設計

- title: `{表示名} (@{username}) - connpass`
- description: 自己紹介の先頭 N 文字 + 「参加 X 件 / 管理 Y 件」
- image: プロフィールアイコン
- type: profile
- profile:username

## 計測すべき指標

- プロフィールページの自己訪問率（自分のページを見る頻度）
- 他者プロフィールへの遷移率
- フォローボタン押下率
- 外部 SNS リンククリック率
- プロフィール完成度（埋まっている項目の割合）
- プロフィール経由のイベント詳細遷移率
