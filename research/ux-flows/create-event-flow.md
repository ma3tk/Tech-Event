# グループ作成〜イベント公開〜参加者管理〜開催後までのフロー

connpass のヘルプセンターと主催者機能群を観察し、イベント主催者が体験する一連のフローを整理する。グループは「単発イベントのために作成する」ケースも「継続コミュニティとして作成する」ケースもあるが、まずグループありき。

---

## 0. 全体像

```
[グループ作成] → [グループ設定] → [イベント新規作成] → [参加枠設計]
   → [プレビュー] → [公開] → [告知] → [参加者管理]
   → [リマインダー送信] → [当日受付] → [出席記録]
   → [事後フォロー] → [資料アップロード] → [アンケート集計] → [統計確認]
```

---

## 1. グループ作成 (Group)

ヘルプ「グループを作成する」より、入口は「ヘッダーの『イベント管理』＞『グループを作成する』ボタン」。

### 1.1 必須入力
| 項目 | 説明 |
|---|---|
| グループ名 | 必須 |
| サブドメイン | `{xxx}.connpass.com`。**後から変更不可** (運営問合せで例外対応) |

### 1.2 任意入力
- グループサブタイトル
- 主催組織名 (organization)
- カバー画像 (グループページの上部)
- サムネイル画像 (アイコン)
- 背景色 (ブランドカラー。配下イベントの背景にも適用される)
- グループ説明 (Markdown 対応 / 文字サイズ・色・区切り線・リンク)
- 共同管理者の追加
- 公式サイト / X アカウント / Facebook ページのリンク

### 1.3 注意点
- 非公開グループ設定はない (オープンコミュニティ原則)
- メンバー追加は基本的に「ユーザー自身が参加する」形だが、CSV/TSV (名前, メールアドレス) で管理者が一括追加することも可

### 1.4 UI フロー
1. ヘッダー > 「イベント管理」 > 「グループを作成する」
2. 必須項目入力 → リアルタイムでサブドメインの衝突チェック
3. プレビュー画面 (グループページのレイアウト)
4. 「作成」ボタン → グループ詳細ページへリダイレクト
5. 自分は自動的に `GroupAdmin.role=owner` として登録される

## 2. グループ運営の初期設定

### 2.1 管理者追加
- ヘルプ「イベント・グループの管理者を追加する」より、編集ページで管理者名 (connpass ユーザー名) を入力
- 候補がオートコンプリートで表示される
- 追加された管理者は同等の編集権限を持つ

### 2.2 メンバー招待
- 「メンバーになる」ボタンの URL をシェア
- グループのイベント告知メール購読者を増やすために初期メンバーの紹介を促す

### 2.3 ブランディング
- カバー画像とサムネイルを設定
- 背景色を組織カラーに合わせる (Findy なら緑、LayerX なら黒など)

---

## 3. イベント新規作成

ヘルプ「イベントを作成する」によると、編集画面のフィールドは多岐にわたる。

### 3.1 基本情報セクション
- グループ選択 (複数のグループの管理者であれば選択肢)
- イベントタイトル
- サブタイトル (catch)
- イベント画像 (最大 1MB)
- イベント説明 (Markdown 対応)
- ハッシュタグ (X 連携用、1 件)

### 3.2 開催情報
- 開始日時・終了日時 (タイムゾーン JST)
- イベント形式 (会場 / オンライン / ハイブリッド)
- 会場名・住所・地図 (オンラインの場合は URL のみ)
- 「参加確定者のみ閲覧可」の情報枠 (オンライン URL、入館情報)

### 3.3 参加受付セクション
- 参加受付方法 (connpass で受付 / 受付なし)
- 募集開始日時・募集締切日時
- 参加枠の設定 (複数可能)
  - 枠名 (デフォルト「参加枠1」)
  - 定員
  - 料金タイプ (無料 / 会場払い / 前払い)
  - 受付方式 (先着 / 抽選 / 指名)
- 重複参加許可設定 (1 ユーザーが複数枠に申し込めるか)

### 3.4 抽選方式の設定
- 「参加受け付け方法」で『抽選・指名』を選択
- 抽選発表日 (lottery_announce_at) を必須入力 (募集開始 ≤ 抽選発表日 ≤ 開催日)
- 抽選発表日以降の申込は先着順に切り替わる
- 指名 (招待) で特定ユーザーを優先確定できる (抽選日まで変更可)

### 3.5 出席管理セクション
- 出席コード設定 (自動生成 or カスタム)
- QR コード出席の許可
- 主催者の手動出席チェック

### 3.6 公開設定
- ドラフト保存
- 即時公開
- プライベートリンク (URL を知る人のみ)

### 3.7 通知・SNS 連携
- 公開時の X 自動投稿
- グループメンバーへの一斉メール

---

## 4. プレビューと公開

### 4.1 プレビュー
- イベントページの完成形プレビュー
- スマホ表示の確認
- OGP プレビュー (SNS シェア時の表示)

### 4.2 公開アクション
- 「公開する」ボタン押下 → `Event.status=published`, `published_at` セット
- `Notification(kind=event_published)` をグループメンバー全員に発火
- X / Facebook 連携が ON なら自動投稿
- グループのフィードに即時反映

### 4.3 公開後の編集制限
- 重要フィールド (日時、会場、定員) を変更すると参加確定者全員に変更通知が送られる
- 定員を減らす操作は「強制キャンセルにつながる可能性」を警告

---

## 5. 公開後の告知活動

### 5.1 ビルトイン告知
- グループメンバーへの一斉メール
- connpass トップページの新着エリア掲載
- 検索インデックス追加
- 関連イベント / おすすめ枠への露出

### 5.2 自前告知
- 主催者が SNS で URL シェア
- ハッシュタグでまとめ
- 動画・ブログでの紹介

### 5.3 ブースト機能 (有料広告)
- カンファレンス特集枠への掲載申請
- ヘッダー広告枠 (FAQ「広告掲載」項目あり)

---

## 6. 参加者管理 (申込中)

### 6.1 管理画面の構成
- 申込者リスト (枠別タブ)
- 状態フィルタ (参加者 / 補欠 / キャンセル)
- 申込日時順 / 名前順のソート
- 出席チェック列
- 「メッセージ送信」ボタン (audience 選択)
- CSV エクスポート

### 6.2 強制キャンセル
- 規約違反者や重複申込者を主催者が強制キャンセル可能
- 操作と同時にユーザーへメッセージ送信可能
- `AuditLog.action=participant.force_cancel` で記録

### 6.3 メッセージ送信
- 一括メッセージのオーディエンス: accepted / waiting / cancelled / all
- 件名・本文・送信プレビュー
- 送信履歴を Message テーブルに保持

### 6.4 受付票発行
- 紙のチケット / バウチャー PDF 出力
- QR 付き

---

## 7. 抽選日 (lottery_announce_at)

- 0〜2 時に cron が自動実行
- pending → accepted / waiting に確定
- 全申込者にメール通知 (kind=lottery_result)
- 主催者ダッシュボードに「抽選完了」通知

---

## 8. リマインダー

### 8.1 自動リマインダー
- 開催 24h 前: 全参加確定者にメール
- オンラインイベントは開催 1h 前にも

### 8.2 主催者カスタム送信
- 「メッセージ送信」機能で会場詳細・登壇順を共有

---

## 9. 当日受付

### 9.1 物理イベント
- iPad / スマホで主催者画面を開き、参加者リストから順次出席チェック
- QR コードリーダーで参加者の受付票を読み取り
- 名簿の CSV エクスポートをバックアップに用意

### 9.2 オンラインイベント
- 出席コードを開始 5 分前に Zoom / X で告知
- 参加者は自分で出席コードを入力
- 参加証明として SNS シェア可

### 9.3 ハイブリッドイベント
- 会場枠とオンライン枠で出席方式を変える運用が一般的

---

## 10. 開催後の事後フォロー

### 10.1 資料公開
- PresentationMaterial を発表者ごとに登録
- Speaker Deck / SlideShare / GitHub URL を貼り付け
- イベントページとグループページ両方に表示

### 10.2 アンケート
- Survey.trigger=after_event を発火 (cron が終了から N 時間後にメール)
- 参加者は SurveyAnswer に回答

### 10.3 統計確認
- EventStat (PV / UU / 申込数 / キャンセル数 / 出席率)
- グループ別の累積イベント数・累積参加者数
- 参考に「グループ統計」「イベント統計」FAQ が存在

### 10.4 SNS まとめ
- イベントハッシュタグで X タイムラインを埋め込み
- togetter 連携など (主催者の任意)

---

## 11. 領収データ発行

有料イベントの場合:
- ヘルプ「領収データ発行」より、参加者の依頼で発行
- 主催者は領収書テンプレート (組織名 / 但し書き) を設定
- 一括 PDF ダウンロード

## 13. UX 上のポイント

### 13.1 段階公開 (ドラフト → 公開)
- 主催者は途中保存で安心して編集できる
- 公開ボタンは目立つが「公開後は重要変更が制限される」旨を表示

### 13.2 複数管理者の並列編集
- 同時編集時の競合検知 (updated_at 比較で楽観ロック)
- 「他の管理者が編集中です」表示

### 13.3 抽選方式の心理的安心感
- 「先着順だと弾かれるかも」という不安を抽選にして払拭
- 主催者にとっては「申し込み総数を最大化」できるメリット
- 参加者からも「じっくり検討できる」と評価されている (ヘルプより引用)

### 13.4 主催者の負担軽減
- メッセージ一括送信
- 出席コードによる自己出席
- CSV エクスポートで名刺交換会など外部活用

## 15. KPI / 計測指標

- **公開所要時間**: 「作成開始」→「公開」までの平均時間
- **公開後告知効果**: 公開直後 24h の申込数
- **抽選方式採用率**: 抽選 vs 先着の比率
- **強制キャンセル率**: 主催者操作の頻度
- **出席率**: accepted のうち attended に至った比率
- **アンケート回答率**: after_event 配信に対する回答率
- **資料公開率**: 開催後 1 週間以内に資料 1 つ以上が登録された比率
- **再開催率**: 同グループの次回イベントが作成されるまでの平均日数

これらを EventStat と AuditLog から算出できる。
