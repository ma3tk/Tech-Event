# イベント発見〜参加申込〜抽選結果〜参加〜キャンセルまで

connpass の参加者視点での体験を、発見から開催後までの全プロセスにわたって追跡する。

---

## 0. 全体像

```
[イベント発見] → [詳細閲覧] → [参加意思] → [申込ボタン] → (要ログイン) 
   → [参加枠選択] → [アンケート/決済] → [申込確定]
   → [(抽選結果)] → [リマインダー] → [当日参加] → [出席]
   → [(キャンセル)] → [事後アンケート]
```

イベントとの最初の接点は複数ある:
- connpass トップ / 新着 / おすすめ
- 検索結果
- グループメンバーへの告知メール
- リマインダーメール
- 外部からの URL シェア (X / Slack / Discord)
- 友人からの口コミ

---

## 1. イベント発見

### 1.1 検索フロー
- ヘッダーの検索ボックスにキーワード入力
- フィルタ:
  - 開催地 (都道府県、オンライン)
  - 開催日 (今日 / 今週 / 来週 / 月別)
  - タグ
  - 参加費 (無料のみ / 有料含む)
  - 受付状態 (募集中のみ)

### 1.2 ブラウジング
- 新着順イベント一覧 (/explore/)
- 人気ランキング
- カンファレンス特集
- 直近開催イベント
- グループ別 (favorite group のフィード)

### 1.3 おすすめエンジン
- メンバーになっているグループの新着
- 参加履歴のあるグループの新着
- ブックマーク履歴を考慮したレコメンド

---

## 2. イベント詳細閲覧 (未ログイン可)

### 2.1 ページ構成
- タイトル / サブタイトル
- カバー画像
- 主催グループ名 + 管理者
- 日時 (タイムゾーン明示)
- 会場 (地図 or オンライン表記)
- ハッシュタグ
- 説明本文 (Markdown)
- 参加枠リスト (枠名 / 料金 / 残席)
- 参加者リスト (アイコン + ニックネーム、人数バッジ)
- 補欠リスト
- コメント欄
- 関連リンク (同グループの過去イベント、発表資料)

### 2.2 サイドバー
- 「参加者」「補欠」の数値表示
- 「申し込み締切まで X 日」カウンター
- 「主催者プロフィール」
- 「SNS シェア」ボタン (X / Facebook)
- 「カレンダーに追加」 (ics ダウンロード)
- 「ブックマーク」アイコン (要ログイン)

### 2.3 動的要素
- 募集中 / 終了 / 開催中 / 開催済 / 中止 のバッジ
- 「あと N 人」「補欠 N 人」のリアルタイム更新

---

## 3. 参加申込導線

### 3.1 申込ボタンの状態
- 「このイベントに申し込む」(募集中・未申込)
- 「キャンセルする」(申込済み)
- 「補欠登録する」(満員)
- 「募集終了」(締切後)
- 「定員に達しています」(満員かつ補欠無効)

### 3.2 ログインチェック
- 未ログイン → ログイン画面に `next` パラメータ付きリダイレクト
- メール未確認 → 確認ガイドモーダル
- ブラックリスト登録ユーザー → エラー表示

### 3.3 参加枠選択画面
- 複数枠がある場合、ラジオボタンで選択
- 各枠に料金・残席・受付方式を表示
- 「重複参加不可」の場合は選択済み枠と排他

### 3.4 申込確認 + 追加入力
- 申込前アンケート (Survey.trigger=on_apply)
  - 必須項目をマーク
  - 入力中の自動保存
- 有料イベント
  - PayPal 決済への遷移
  - バウチャーコード入力欄
  - 金額確認

### 3.5 申込確定
- 先着: 即時 accepted (or waiting)
- 抽選: pending、抽選発表日 (lottery_announce_at) を表示
- 完了モーダル
  - 参加ステータスの明示
  - 「マイページへ」「グループに参加」「SNS シェア」
  - カレンダー追加リンク

### 3.6 自動グループ参加
- ヘルプ通り、申込と同時に `GroupMember.joined_via=event_join` で自動加入
- グループに既にメンバーであればスキップ
- これにより以降そのグループの告知メールが届く

---

## 4. 抽選結果待ちフェーズ

### 4.1 抽選方式の表示
- イベント詳細に「抽選発表日: YYYY/MM/DD」表示
- 申込後のマイページに「抽選結果待ち」ラベル

### 4.2 抽選 cron 実行
- 抽選発表日の 0〜2 時に自動実行
- nominated フラグの参加者を最優先確定
- 残りはランダムにシャッフルして上から定員分を accepted、それ以降を waiting

### 4.3 結果通知
- メールで「参加確定」または「補欠」を通知
- マイページに即時反映
- SNS シェアボタンで結果共有 (希望者のみ)

### 4.4 発表後の追加申込
- 抽選発表日以降は先着順に切替
- 「補欠から繰り上がる可能性」を案内

---

## 5. リマインダー

### 5.1 24h 前リマインダー
- 全参加確定者にメール
- 日時 / 会場 / 持ち物 / 出席方法を再掲

### 5.2 オンライン: 開催 1h 前
- Zoom URL や出席コードを記載

### 5.3 直前変更通知
- 主催者がイベントを編集した場合 (日時 / 会場変更等)
- 全参加確定者に通知 `Notification(kind=event_updated)`

---

## 6. 当日参加 / 出席

### 6.1 物理イベント
- 受付で名前または QR 提示 → 主催者がチェック
- 受付票印刷推奨

### 6.2 オンラインイベント
- 配信 URL にアクセス
- 出席コードがフォームに表示されたら入力
- 開始 2h 前から終了時刻まで入力可能

### 6.3 出席完了
- マイページに「出席済み」バッジ
- 累積出席数として記録

### 6.4 ハイブリッド
- 物理 / オンラインそれぞれの方式
- 主催者が両方の出席を集計

---

## 7. キャンセルフロー

### 7.1 キャンセルボタン
- イベントページ・マイページの両方に「キャンセルする」ボタン
- ボタン押下で確認モーダル
- 確認後 `Participant.status=cancelled`、`cancelled_at` セット

### 7.2 補欠繰り上がり連鎖
- accepted のキャンセルで waiting 先頭が accepted に昇格
- メール通知 (`Notification.kind=promoted_from_waiting`)
- 連鎖中も他ユーザーのキャンセルにロックを取って整合性を保つ

### 7.3 有料イベントのキャンセル
- 主催者の規約に従う
- 返金可能なら Payment.status=refunded
- 規約上不可なら主催者問い合わせを案内

### 7.4 キャンセルマナー
- ヘルプは「できるだけ早くキャンセルを」と明記
- 何度もキャンセルするユーザーには警告 (主催者の判断でブラックリスト)

---

## 8. 事後フォロー

### 8.1 資料閲覧
- イベントページに発表資料リンクが追加される
- マイページの「参加履歴」から過去資料を辿れる

### 8.2 事後アンケート
- 主催者が Survey.trigger=after_event を設定していれば自動メール
- 回答インセンティブ (主催者裁量) と再エンゲージメント機会

### 8.3 同グループの次回イベント
- 自動グループメンバーになっているため、次回告知が届く
- マイページの「あなたへのおすすめ」にも掲載

---

## 9. ブックマーク機能

### 9.1 ブックマーク追加
- イベント詳細のブックマークアイコン
- 興味あるが申込未定のイベントを保存
- ログインユーザーのみ

### 9.2 ブックマーク一覧
- マイページ > ブックマーク
- 募集開始通知の有効化オプション
- 募集開始時に `Notification(kind=bookmark_event_started)`

---

## 10. 失敗ケースと UX

### 10.1 申込集中時の競合
- 人気イベントは公開直後に申込が集中
- アプリ層で `SELECT FOR UPDATE` でロック → 定員超過時は即補欠回し
- フロントは楽観的に申込確定を表示しつつ、サーバ確定で再描画

### 10.2 メールが届かない
- 確認: 迷惑メールフォルダ / 配信停止状態 / メアドのタイプミス
- ヘルプ「メール配信を停止したい」「メールが届かない」に対応手順

### 10.3 ニックネーム被り
- 一意制約、登録時にチェック

### 10.4 同一イベントへの重複申込
- デフォルト不可 (allow_duplicate_join=false)
- 主催者が許可した場合のみ複数枠への重複申込が可能

## 12. 重要な UI 状態の網羅

下記を組み合わせて、参加申込ボタンの表示を分岐:

| 募集状態 | 自分の申込状態 | 定員 | ボタン表示 |
|---|---|---|---|
| 募集前 | - | - | 「募集開始日: YYYY/MM/DD」 |
| 募集中 | 未申込 | 残席あり | 「このイベントに申し込む」 |
| 募集中 | 未申込 | 満員 (補欠許可) | 「補欠登録する」 |
| 募集中 | 未申込 | 満員 (補欠なし) | 「定員に達しています」 |
| 募集中 | 申込済 (accepted) | - | 「キャンセルする」+ 出席案内 |
| 募集中 | 申込済 (waiting) | - | 「キャンセルする (補欠登録中)」 |
| 募集中 | 申込済 (pending) | - | 「抽選結果待ち」 |
| 募集中 | キャンセル済 | 残席あり | 「再申込する」 |
| 募集終了 | 未申込 | - | 「募集は終了しました」 |
| 開催中 | 申込済 | - | 「出席する」(コード入力 / Zoom URL) |
| 開催済 | accepted, 出席済 | - | 「参加済み」 |
| 開催済 | accepted, 未出席 | - | 「欠席」 |
| 中止 | - | - | 「このイベントは中止されました」 |

## 13. アクセシビリティ配慮 (参加者視点)

- 申込ボタンはフォーカスインジケータを明示
- 色だけでなくテキストラベルで状態を伝達
- スクリーンリーダ向けに「申込状況: 参加確定」などの aria-label
- 数値変動は aria-live="polite" で読み上げ

---

## 14. KPI / 計測

- **発見 → 詳細閲覧率**
- **詳細閲覧 → 申込率** (CVR)
- **申込 → 出席率**
- **キャンセル率** (申込 → cancelled 比率)
- **補欠繰り上がり率** (waiting のうち最終 accepted)
- **抽選当選率** (lottery 申込のうち accepted)
- **ブックマーク → 申込率** (ブックマークの効果)
- **メール開封率 / クリック率** (リマインダー、抽選結果)

これらの指標は EventStat と Notification の sent / read 列、Participant 状態遷移の AuditLog から算出できる。
