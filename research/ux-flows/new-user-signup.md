# 新規ユーザー登録〜初回イベント参加までのフロー

connpass.com を観察すると、新規ユーザーが「気になるイベントを見つけて参加する」までの最短経路は極めて短いことが分かる。本書ではトップページからの導線、登録 UI、初回参加の流れを整理する。

---

## 0. 全体像

```
[トップ閲覧] → [イベント発見] → [参加申込ボタン] → [ログイン要求]
   → [新規登録 or SNS 連携] → [メール確認] → [参加枠選択] → [参加確定]
   → [リマインダー] → [当日出席]
```

途中で離脱しても再開できる点が重要。connpass はイベント詳細ページを公開にしているため、未ログインユーザーでも内容を確認したうえで登録に進める。

---

## 1. トップページからの発見

### 1.1 トップページの主要要素
- ヒーロー: 「エンジニアをつなぐIT勉強会支援プラットフォーム」のキャッチコピー。
- CTA ボタン 2 種: 「connpass をもっと詳しく」(/about/) と「イベントを作成する」 (グループ作成導線)。
- 6 機能紹介セクション (見逃さない / イベントを育てよう / IT勉強会にピッタリ / 事前決済の手数料は業界最安値 / 参加者のための便利機能 / 多彩なイベント告知)。
- おすすめグループセクション (LayerX、Findy、DeNA Tech、StudyCo、AI 駆動開発、PyCon JP)。
- 新着イベント一覧 (カード形式)。

### 1.2 イベントカードに表示される情報
- 開催日 (月日)
- 開催前 / 募集中 などのステータス
- 公開日
- 主催グループ名 (リンク)
- 管理者のアイコンと名前
- イベントタイトル (リンク)
- 簡潔な説明文
- 開催場所 (住所 or 「オンライン」)
- 参加者数 / 定員 (「0/45 人」形式)

### 1.3 検索とフィルタ
- ヘッダーに常時表示の検索ボックス。キーワードでイベント検索が即座にできる。
- サイドバーから「直近開催」「ランキング」「カンファレンス特集」へジャンプ。

ユーザーは初訪問時にここまでの情報をログインなしで閲覧できる。

---

## 2. 参加意思の発生

イベント詳細ページに遷移すると以下を確認できる:

- イベント本文 (Markdown)
- 日時・会場・ハッシュタグ
- 参加枠の名称・料金・残席
- 参加者リスト
- 主催者プロフィール
- 過去の参加者数や同グループの他イベントへのリンク

ここで「このイベントに申し込む」ボタンを押すと、未ログインの場合はログイン/新規登録画面にリダイレクトされる。`?next=/event/{event_id}/` のようなパラメータで申込画面に復帰できる設計が望ましい。

---

## 3. 新規登録フロー

### 3.1 入口
ログイン画面には「会員の方は、登録時に利用した X(Twitter) / Facebook / GitHub のボタンからログインすることができます」と記載。新規登録は次の 4 経路。

1. メールアドレス + パスワード
2. X (旧 Twitter) OAuth
3. Facebook OAuth
4. GitHub OAuth

### 3.2 メールアドレス登録の詳細手順
1. メールアドレス入力 → 「確認メール送信」
2. メール内のリンクをクリック (有効期限あり)
3. ユーザー名 (nickname、URL に使われる)、表示名、パスワードの設定
4. 利用規約・プライバシーポリシーへの同意チェック
5. 登録完了 → 自動ログイン
6. 直前に閲覧していたイベントの申込画面へリダイレクト

メールアドレス登録時の検証:
- メール形式
- ニックネームの一意性 (`/user/{nickname}/` で衝突回避)
- パスワード強度 (8 文字以上、英数字混合推奨)
- 確認メールが届かない場合の再送機能 (FAQ「新規登録の確認メールが届かない」項目あり)

### 3.3 SNS 連携の流れ
1. プロバイダ OAuth 画面で許可
2. connpass 側で `OAuthIdentity` 作成
3. メールアドレスが取得できれば自動でアカウント発行、できなければ補完入力
4. ニックネームを自動生成 (例: `@xxx_yyy_12345`) → 後で変更可

### 3.4 登録後オンボーディング
- プロフィール完成度の促し (アバター・所属の入力リンク表示)
- 「あなたへのおすすめイベント」表示 (タグ・周辺ジオから推定)
- 「興味のあるグループに入る」ボタン
- メール通知設定 (デフォルト全 ON、後で切替可)

---

## 4. メール確認 (重要なゲート)

ヘルプ「イベントに参加する」に「メールアドレスの登録・確認が完了している必要があります」と明記。

- メール確認が未完了の場合、参加申込ボタンを押すと「メール確認を完了してください」モーダルが表示される。
- 確認メール再送リンクが付随。
- SNS 登録時にメールが取れない場合は別途メール登録フローが必要。

これは不正登録防止と通知到達性のための必須ゲート。

---

## 5. 初回イベント参加申込

### 5.1 参加枠の選択
- イベントによっては「一般枠」「LT 枠」「学生枠」などの複数参加枠あり。
- 各枠に料金・定員・現在の状況 (満員 / 残席あり / 補欠) が表示される。

### 5.2 申込確認画面
- 選んだ参加枠の最終確認
- アンケート (Survey.trigger=on_apply) があれば回答必須項目を表示
- 有料イベントの場合は PayPal 決済画面へ
- 「規約を確認してから申し込む」チェックボックス

### 5.3 申込確定
- 先着方式: 即時 `accepted` または `waiting` (定員超過時)
- 抽選方式: `pending` で保留、抽選発表日 (lottery_announce_at) を表示
- 申込完了画面に「マイページに戻る」「グループに参加する」「SNS でシェア」のボタン

### 5.4 自動的なグループ加入
- ヘルプ「グループのメンバーになる」より、「申し込みすると、自動でグループに参加する」記述あり。
- `GroupMember.joined_via=event_join` で記録。
- 以降そのグループの新着イベント告知が届く。

---

## 6. 申込後の確認

### 6.1 確認メールの内容
- 申込ありがとうメール
- 「あなたの参加ステータス: 参加 / 補欠」
- イベントの日時・場所
- キャンセル方法へのリンク
- カレンダー (.ics) 添付

### 6.2 マイページ
- 「あなたのイベント」セクション
- 申込済みイベントが日付順に並び、「キャンセルする」ボタン
- 過去のイベント (出席 / 欠席履歴) を確認可能

### 6.3 リマインダー
- 開催 24h 前にリマインダーメール (`Notification.kind=reminder_24h`)
- オンラインの場合は当日 1h 前にもリマインダー
- リマインダー内に出席コードや会場アクセス情報を含む

---

## 7. 当日の出席

ヘルプ「イベントに出席する」より、出席方法は 3 通り:

### 7.1 出席コード入力 (オンライン推奨)
- 主催者が公開した 4〜6 桁の出席コードを参加者が自分でフォームに入力
- 「イベント開始 2 時間前から終了時刻まで」の時間制限
- 入力成功で `Participant.status=attended`

### 7.2 主催者による手動チェックイン
- 物理イベントで受付係が iPad などで「出席」ボタンを押す

### 7.3 QR コード読取
- 参加者のマイページに表示される QR を主催者がスマホで読み取る
- iOS / Android 両対応
- 主催者側の事前ログインが必須

---

## 8. 補欠だった場合のフロー

- 当初は `waiting` ステータス
- 上位参加者がキャンセルすると自動で `accepted` に昇格
- 昇格時にメール通知 (`Notification.kind=promoted_from_waiting`)
- 参加者は通知から再度マイページにアクセスし、出席意思を再確認できる

---

## 9. キャンセル時のフロー

- 「キャンセルするボタン」がイベントページに表示される
- クリックでモーダル確認 → `cancelled` へ遷移
- ヘルプには「できるだけ早く参加キャンセルを行うようお願い」と明記
- 有料イベントの場合は返金規約に従う

---

## 10. UX 上のポイント

### 10.1 摩擦の少ない導線
- イベント本文は未ログインでも閲覧可能 → 興味喚起後のログインを最小化。
- SNS 連携を 3 種類用意することで、登録段階の心理的ハードルを下げている。
- ニックネームの自動生成で「URL に使えないニックネーム」エラーを抑制。

### 10.2 メール検証の徹底
- 主催者から参加者へ重要通知 (会場変更、キャンセル等) が確実に届くことが運営上の生命線。
- そのためメール未確認では参加申込できない厳格な設計。

### 10.3 ステータスの可視化
- 申込結果が「即確定 / 抽選保留 / 補欠」のどれかを画面と通知で明確化。
- マイページから自分のすべての申込状況を一覧確認できる。

## 12. KPI / 計測ポイント

このフローで取得すべき指標:

1. **登録コンバージョン率**: 申込ボタンクリック → 登録完了率
2. **メール確認率**: 登録完了 → メール確認完了率（24h 以内）
3. **初回参加申込率**: メール確認 → 初参加申込完了率
4. **初回出席率**: 初参加申込 → 出席率
5. **SNS ログイン比率**: メールアドレス vs X vs Facebook vs GitHub の比率
6. **離脱地点ヒートマップ**: 申込画面 / 参加枠選択 / アンケート / 決済 のどこで離脱が多いか

これらは AuditLog と Notification の sent/read タイムスタンプから算出できる。
